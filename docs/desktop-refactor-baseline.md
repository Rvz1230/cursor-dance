# CursorDance 桌面端重构基线

> 状态：已完成
> 基线提交：`c196e2b`
> 采集日期：2026-07-28
> 静态采集环境：macOS arm64、Node.js 22.23.1、Vite 7.3.6
> 动态采集环境：macOS arm64、采集器 Node.js 22.23.1、Electron 42.4.0（内置 Node.js 24.16.0、Chrome 148.0.7778.254）

本文件保存桌面端重构前的代码量、构建体积、配置载荷和动态运行基线。所有数值均由同一脚本在隔离配置下实测，不使用估算值。

## 1. 复现方式

完整采集（包含 Electron 启动、CPU、内存和 IPC 压力）：

```bash
npm run measure:desktop-baseline
```

仅采集代码量、构建体积和配置载荷：

```bash
npm run measure:desktop-baseline:static
```

脚本位于 `scripts/measure-desktop-baseline.mjs`。完整采集使用隔离的临时 `userData`，并启用桌面 smoke 模式，不启动全局输入监听、托盘、AI 服务和自动更新器。

## 2. 统计口径

- 有效代码行：排除空行和纯注释行；生产代码与 `*.test.*` / `*.spec.*` 分开统计。
- 桌面代码：`src/desktop`。
- 扩展运行时：`extension/config-runtime` 与 `extension/content-runtime`。
- 共享 Workbench UI：`src/app/pages/theme-workbench` 与 `src/components/ui`。
- 页面 bundle：统计对应 HTML 直接引用的入口、共享 chunk 和 CSS，分别记录原始与 gzip 大小。
- 图片主题载荷：在默认配置的首个主题中加入 256 KiB data URL 数据，测量完整 JSON；该夹具用于比较配置传输放大，不代表推荐图片尺寸。

## 4. Renderer 构建体积

| 入口 | 原始大小 | gzip 大小 | 直接引用资源数 |
|---|---:|---:|---:|
| Workbench | 1,966.0 KiB | 410.8 KiB | 5 |
| Overlay | 165.3 KiB | 36.0 KiB | 3 |
| Popup | 764.9 KiB | 170.7 KiB | 4 |

Renderer 输出总大小为 2,106,709 bytes（约 2.01 MiB）。Workbench 是首要拆包对象；Popup 直接复用较大的共享 UI chunk，在决定保留或删除该入口前不做孤立的微优化。

## 5. 配置与 IPC 载荷

| 场景 | JSON 大小 |
|---|---:|
| 默认配置 | 44,990 bytes（43.9 KiB） |
| 含 256 KiB 图片 data 的配置 | 569,596 bytes（556.2 KiB） |

图片夹具使配置增加 524,606 bytes，约为输入数据的两倍。主要原因是当前配置同时序列化 `themePacks` 和兼容别名 `schemes`；两者即使在内存中引用同一数组，JSON/IPC 仍会重复编码。后续 schema 重构应只保留一个规范字段，并把大图片资产从高频配置广播中拆出。

## 6. 动态运行基线

本机已完成正式动态采集：

| 指标 | 基线值 |
|---|---:|
| 冷启动到 Workbench ready | 1,127.2 ms |
| 显示器 / overlay / Workbench | 2 / 2 / 1 |
| 空闲主进程 CPU | 0.198% |
| 空闲总工作集 | 852,912 KiB（约 832.9 MiB） |
| 1,000 次 mousemove 实际耗时 | 1,001.0 ms |
| 目标 / 实际源事件频率 | 1,000 / 998.997 Hz |
| 发出的 overlay IPC | 2,000 条 |
| 压力期间主进程 CPU | 0.685% |

空闲工作集分布：

| 进程类型 | 数量 | 工作集 |
|---|---:|---:|
| Browser | 1 | 174,016 KiB |
| GPU | 1 | 190,016 KiB |
| Utility | 1 | 39,840 KiB |
| Tab | 3 | 449,040 KiB |

采集器已强制要求 Node.js 22.12.0 以上，并按目标时间补齐事件；本次 1,000 Hz 压力采样实际达到 998.997 Hz，误差约 0.1%。双显示器下每个源事件向两个 overlay 各发一条 IPC，因此总消息数为 2,000。

动态值与机器、显示器数量和系统负载有关。后续对比必须使用相同机器、Node/Electron 版本、显示器配置和采样脚本；建议每次至少运行三次并记录中位数。

## 7. 当前结论

1. Workbench 页面体积明显高于 overlay，是 UI 拆分和延迟加载的优先对象。
2. 桌面与扩展运行时合计超过一万行生产代码，共享核心重构具备明确的精简空间。
3. 图片随完整配置广播会被兼容别名放大约两倍，配置单一真值与资产分离应先于进一步缓存优化。
4. R0-3 静态与动态基线均已完成；R0-1 的类型、版本和 lint 护栏也已补齐，Phase 0 已结束。
