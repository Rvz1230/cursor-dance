Toast ui/toast.tsx + shell.js 的 toast()；一次性结果，2.6s 自动消失

带撤销是默认，不是可选（决策 #7）：一个没有撤销出口的一次性提示只是在通知用户「已经来不及了」。 第三个按钮是元操作——toast() 除了弹提示还顺手做两件事（压撤销栈、把草稿标脏）， 而「应用到桌面」自己也弹 toast，于是它先把脏标记清掉、紧接着 toast 又标回去， 实测点完之后作用域条照旧显示「未应用」。所以第三个参数把「这是一次配置改动吗」显式化： 一个函数默默替调用方决定语义，就一定会有一天决定错。 真实实现只有一处（shell.js 的 toast()）；库页不套外壳，所以这里自起一个 host， markup 与它逐字相同。实现时 toast 要走令牌层——shell.js 那份写死了 bg-white，深色下会是一块白板。

第五个 tone 是 neutral（中性底，用于「这里为什么是空的」这类既非成功也非警告的说明）。 role 要跟着分量走：status 是礼貌播报， 出错那一条用 alert（打断当前朗读）——两者用同一个 role 的话，读屏用户要么被每条提示打断，要么错过真正的错误。

深色模式：语义令牌层（这一页是它唯一的验证处）

决策 #10 写着「令牌层已在 library/components.html 验证」。本轮实测那句话是假的： 深色下有 14 个元素与容器同色（对比度 1.00），其中滑块的已填充段整段消失——深色下读不出当前值。

两处改动都不是「补个色」：
底色从两层变三层——界面实际有三层（页面底 → 卡片 → 卡片里的小面板）， 第三层原先复用 surface，浅色下靠描边还能读，深色下就是 slate-900 套 slate-900。 浅色靠 ring 分隔、深色靠更亮一档填充：两种模式用不同手段表达同一件事，因为浅色能往下压、深色只能往上提。
文字从四级删成三级——上一版这张表写着 ink-4 浅色是 slate-400， 而 _src.css 里它是 slate-500，与 ink-3 计算值逐位相同（都是 rgb(100,116,139)）。 也就是说第四级只存在于这张表里，而这张表是这一层唯一的文档。 为什么不能真给它 slate-400：白底上约 2.6:1，连非文本图形的 3:1 都不到——那正是它当初被提到 500 的原因。 删掉一个假层级，比让表说一句真话更对。

功能色（emerald / rose / sky / amber）在深色下换 -300 字色 + -950 底色。 做完这一层，其余页面是机械替换——而「机械」的判据是页面里不再手写 dark:： 这一页上一版有 74 处，其中 btn-outline 与 kbd 共 11 处是在重复它们自己的类里已经写好的深色分支。
