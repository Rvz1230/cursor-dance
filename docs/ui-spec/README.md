# CursorDance 前端重构 UI 规范

这套稿子是**前端彻底重构的依据**，不是示意图。每一页都可点击、交互真实，参数与真实运行时对齐，编译用项目自己的 `tailwind.config.js` 尺度。

设计语言沿用现状（`DESIGN.md` 的「克制柔软」：slate 单色骨架 + `rounded-xl` + 1px 描边 + `shadow-sm` + L1–L6 排版层级）。琥珀金身份色那版提案已**否决**，留档在 `archive/`。

## 交互闭环走查后补齐的行为（这一批是排查出来的，不是原始设计）

这些是走查时发现的闭环缺口，已在稿子里实现，重构必须一并带上：

| 行为 | 为什么 |
| --- | --- |
| **时间轴是横跨两列的底部抽屉**，可折叠、可拖高度（150–460px） | 原先挤在右列只有 ~400px 宽，而舞台被压到 212px——装不下自己要展示的效果（粒子扩散直径 176px + 文字上浮 54px）。现在舞台 304px、时间轴 684px。折叠后标题行保留「N 条轨道 · N 条已链接 · 播放头 xxx ms」，否则收起来就失去上下文。 |
| **标尺与轨道的栅格必须严格一致**（132px + gap-2.5 + px-1） | 原先标尺 96px、轨道 112px，刻度与色块错位、播放头偏 5px。播放头位置现在由实测几何算出，不再依赖常量——改布局不会再错一次。 |
| **独奏 S 与静音 M 并存** | 两种不同需求：独奏是「只看这一个」，静音是「排除这一个」。静音轨仍留在时间轴上（标成静音）并仍可作为链接目标。 |
| **循环区间随总长收缩钳制** | 关掉最长通道后区间会落在总长之外，播放卡死。 |
| **链接目标被关掉 → 固化为当时的绝对时间并明确告知** | 原先静默降级，色块会跳位置且不给解释。注意：固化必须在翻转开关**之前**取值，否则算出来的是降级后的 off。 |
| **拒绝链接成环** | A 链 B、B 链回 A 时无解。拒绝并提示，按绝对时间放置。 |
| **「其余 N 项」= 卡内分组折叠 + ⌘K 全局字段搜索** | 一套主题约 390 个配置决策，任何分组都不如直接搜字段名。搜到「其余项」里的字段时会自动展开分组、必要时先打开该效果，并让命中的字段闪一下。 |
| **值的四态溯源**：默认 / 预设 / AI / 自定义 | 字段旁一个小点标来源，双击回到预设值；卡头显示「弹跳 · 2 项已改」；预设 chip 显示「·已改」并给出「回到「弹跳」」。 |
| **撤销栈按主题分桶 + 重做 ⌘⇧Z** | 在主题 A 改了 3 步、切到 B 再 ⌘Z 撤销 A 的改动是错的。撤销函数返回重做函数，两者成对。 |
| **白名单模式与例外列表联动** | 「仅在指定应用中启用」下「关闭」是空操作。切过去后隐藏「关闭」段、把原本关闭的行标「白名单下无效」，并给一个「移除这些空配置」。 |
| **高级规则被例外应用覆盖时标出来** | 裁决顺序是例外 > 高级，被盖住的规则原先毫无提示，用户会反复调它。 |
| **诊断：采集开关（唯一真值）+ 暂停滚动** | 原先「实时接收」开关与「采集未开启」状态是两个纠缠的概念。 |
| **拦截分布可点击筛选** | 「40 次里 11 次被区域过滤」原先只是个数字，点一下应能筛出那 11 组。 |
| **布局预设按钮只在工作台出现** | 只有它是多列界面，放在外壳里会让另外 4 页出现点了没反应的死控件。 |

## 控件统一（这一批是「组件库没落地」的欠债）

`library/controls.html` 当初只是「展示」：界面里照旧用原生 `<input type=range>` 和 `<select>`，
还多出一套 `mini-select`。量化过的欠债是 **25 个原生 range + 4 个原生 select + 4 处 mini-select**。
现在全部收进 `controls.js`，五个界面与两个库页共用同一实现，**原生控件数为 0**。

**还剩一笔同型的欠债，登记在这里而不是默默留着**：分段控件是全稿唯一还在手写 markup 的
控件家族——`01`×10 / `02`×3 / `03`×4 / `04`×3 / `05`×4 / `shell.js`×3 / 库页×4，共 **24 处以上**。
它该收进 `Ctl.segmented`（aria / 键盘 / 单项禁用理由 / 整体禁用收在一处），
理由与滑块、下拉那次逐字相同。本轮没做，因为迁移面是 5 个界面 × 三档窗口；
先在 `library/components.html` 把契约写死并接线（那一页原先的三组演示**一个 handler 都没有**，
点「校准」前后 class 与 aria 逐位相同——而它正是 `Segmented` 的形态依据）。

实现时必须保持的手感约定（这些细节就是「精致」的全部来源）：

- 拖柄 hover 放大、拖拽时出数值气泡、松手才 commit（拖动过程不落 toast）
- 轨道下方一个小三角标出默认值，**双击拖柄回默认**
- 方向键 ±step、Shift ±10step、⌥ 临时关闭刻度吸附
- **标签可横向 scrub**（Blender / AE 手感，不占额外空间）
- 不变量收在 `paint()` 里：键盘、scrub、程序化赋值都经过它，双拖柄的 `v ≤ v2` 不会被绕过
- 禁用态由 CSS 后代选择器承担（`.sl-disabled .sl-fill`），不要用 JS 改类名——`.sl-fill` 是 `@apply` 组件类，元素上没有 `bg-slate-900` 可替换
- 下拉的选项要「长成结果的样子」：缓动画曲线并标过冲百分比、形状画图形、字体用该字体渲染样张

## AI 助手的重新定位（`06-ai.html`）

> **AI 不是配置生成器，是「提案人 + 排障助手」。它永远只产出一份待审补丁，用户是唯一的写入者。**

现状里已经做对、不要动的部分：Agent 在**服务端沙箱副本**上迭代（`createToolExecutor` 里 `configs = {...initialConfigs}` + 快照回滚），不碰真实配置；已有 `diffItems` 的改动详情；已有实时预览；已有 `revertAiChanges` 兜底；Agent 每步可观测。

要改的五处：

| 现状 | 改成 |
| --- | --- |
| 用户先选「快速 / Agent」两种模式（两条 endpoint、两种产物形状） | **取消模式选择**。一次能给出补丁就直接给；需要多步就展开可折叠的过程区。模式是实现细节，不该由用户决定 |
| `applyProposal` 一次写入全部 patch | **逐项接受**。AI 常 80% 对、20% 不对，必须能只接受一部分 |
| `diffItems` 只读、截断 12 条、不指向界面位置 | 每项一行 diff + 接受/跳过开关；**hover 高亮到左侧对应的卡片 / 字段 / 时间轴轨道** |
| AI 只能写扁平字段（`AI_SCHEME_PATCH_FIELDS` 白名单），会**冲掉**用户建立的锚点链接 | 补丁改成 **op 列表，五种 kind**：`preset` / `field` / `timing` / `curve` / `toggle`，一一对应新架构的五个可编辑面。`timing` op 用 `{ref, off}` 表达，所以不会把相对时间冲成绝对时间 |
| AI 看不到运行时，只能做审美建议 | 新增只读工具 `read_timeline` / `read_diagnostics` / `list_presets`，AI 能回答「**为什么没效果**」并给出预算收益 |

工具集：`read_config` / `read_timeline` / `read_diagnostics` / `list_presets`（全只读）+ `propose_patch`（唯一交付口，替代 `finalize_proposal`）。服务端沙箱与 `apply_config_patch` / `rollback` 可保留用于模型自我试算，但**不再是交付路径**。

其余已定：

- `revertAiChanges` 合并进全局撤销栈，只留一套回退；接受后被改字段标 `src: 'ai'`（对上四态溯源）
- **冲突标记**：某个 op 会覆盖用户手改过的值或已建立的链接时，行内明示「会覆盖你手改的字号 28」
- **好用的提案可一键存成自定义预设**，进入预设层复用，不再是一次性的
- **隐私**：诊断含前台应用名，**默认脱敏成「某应用」**，仅在用户显式开启「诊断里带上应用名」时发送真实名称，并在提问区就近说明

## 创作型 Agent —— **已并入 `06`**（形态留档见 `archive/10-agent-merged-into-06.html`）

> **裁决见 `DECISIONS.md` 裁决 7：两条工具链可以并存，两个产品概念不行。**
> 下面这一整节的**技术论证仍然成立**——它论证的是后端能力（受约束的效果 DSL + 无头渲染
> + 客观指标 + 新颖性距离），那条链要建。变的只是入口：不再是第 10 个页面，
> 而是 `06` 意图路由里的「从描述创建新场景」一支。
>
> 为什么合并：`06` 自己那一版就取消了「快速 / Agent」模式选择，理由是
> **「模式是实现细节，不该由用户决定」**。同一条理由在"两个 AI 助手"这一层同样适用。

> **`06` 的调参链在闭区间里选值，交付字段补丁；创作链写效果程序，交付一段规格。
> 前者的上限是「准确率」，后者的上限是「能力」。**

为什么这条链值得单独建：`06` 的动作空间是 `particleStyle: '火花' | '碎屑粒子' | '星光' | …`
这样的枚举，所以那个 agent **永远造不出第 9 种粒子**。而 `compute-specs.ts` 里
`'火花'` / `'碎屑粒子'` / `'星光'` 根本不是原子概念——它们只是硬编码的预设，
产出不同的 `ParticleSpec` 数值（火花是 `motionScale 1.45 / gravityScale 0.35 / 拉长胶囊`，
碎屑是 `gravityScale 1.45 / 带 inset 阴影的方块`）。**枚举是给人用的 UI 抽象，
不该是给 agent 用的动作空间**；IR 已经在那儿了，这一页把它作为交付物暴露出来。

界面上必须成立的四件事，缺任何一件这一版就退化回 `06`：

| # | 要求 | 稿子里的形态 |
| --- | --- | --- |
| 1 | **循环可见** | 生成 → 渲染 → 读指标 → 自我修复 → 复核，九步 spine。第 4 步那次失败（三项超预算）**在最终态里仍然留着**，它是这个 agent 与「一次性出 JSON」的唯一区别 |
| 2 | **指标由程序推导** | `metricsOf()` 从程序本体算峰值同显 / 帧耗时 / 屏占 / 时长；改 `PROGRAMS` 任一个值，五行跟着变，v2 该失败的地方仍然失败。同门禁里「效果卡的 total 不能谎报」 |
| 3 | **新颖性量化** | 「与最近内置预设的距离 0.71」是一等指标。这一项低就说明 DSL 白给了——agent 只是把预设重新发明了一遍 |
| 4 | **人是唯一写入者** | 沿用 `06` 的裁决。交付按「段」（发射器 / 形状 / 时间轨 / 色带）逐段接受，冲突行内明示 |

### 第二轮：四条非顺利路径（首版只有一条顺利路径）

首版只画了「问 → 造 → 自修 → 交付」。走查后的判断是：**真正决定 agent 体验的是另外四件事**，
它们各自对应一个原型态，缺了就只是个 demo。九个原型态里有四个是这一批加的：

| 态 | 缺了会怎样 | 稿子里的形态 |
| --- | --- | --- |
| **② 生成中的「停止」** | 一个要跑九步、每步都在烧钱的循环没有中止入口，用户宁可让它跑完也不敢点 | 停止按钮只在 ②③ 出现；停止后落到 ⑧ 并**保留已算出的 v2 候选**，可以「从 v2 继续」而不是从零重来 |
| **④ 三候选并列** | 创作类任务只给一个答案，用户只能「接受或丢弃」，没有挑的机会 | 同一句需求三种解（棱镜碎片 / 霓虹拉丝 / 像素崩解），各自的帧耗时与新颖性都摆出来；点一行即在舞台试放，选中的才进交付，另外两个存进「这次没选的方向」可召回 |
| **⑥ 需求歧义就反问** | 「像纸屑一样落下」有两种会导出完全不同程序的解，猜错要浪费一整轮渲染 | `ask_user` 工具 + 两个「长成结果的样子」的选项（各自说明生成点在哪）+「两个都试一遍」的出口。并明确**只在两种解会导出不同程序时才问** |
| **⑦ 修不好要有出口** | 连续修复失败时只能装作成功或干丢一句「失败了」 | 三个出口都摆出来并写明代价：放宽帧预算到 10ms（低配可能掉帧）/ 降级到内置预设「礼花」（新颖性归零）/ 保留但仅高性能模式启用。文案明确「停下来问你，而不是交一个假装合格的候选」 |

配套两条：**续写**（交付后意图 chips 从「造什么」换成「基于当前候选怎么调」，并在卡头标
「续写自 霓虹拉丝」——续写与从零重来是两种不同动作，用同一排 chip 会让人以为改一句就要重跑一轮）；
**⌘K 命令面板注册 + ⌘⇧A**（决策 #6 的快捷键体系，否则这一页只能从 06 的按钮旁边被发现）。

这一批又修掉三个缺陷：

1. **`⑦` 原来是一个态 + 一个隐藏变量**（`halt` + `haltReason`）。后果是走查的人点开 ⑦
   根本不知道自己看到的是「修不好」还是「被中止」——取决于上一次点过什么，而这两块的
   文案与出口完全不同。拆成 ⑦⑧ 两个独立原型态，`HALT` 直接按态取值。
   **一个要靠隐藏状态才能解释的原型态，等于没有这个原型态。**
2. **`setProtoLocal` 不写 `body[data-proto]`**（06 也没写）。凡是页面自己驱动的跳转——
   反问选完、候选选定、停止、兜底出口——都会让 body 上的档位停在上一次**手点按钮**时的值。
   现在没有样式依赖，但它是个已经错了的状态。
3. **A/B 试听原来只换按钮文案**，没有任何行为——一个没有行为的装饰控件。
   现在按住放候选、松手回当前，并有一行状态提示说明当前在放哪个。

另外，三个候选**必须真的各自过预算**，而不是卡头上写一句「都已过预算」：
`metricsOf()` 对 A/B/C 分别算出 7.4 / 5.8 / 6.6ms，都在 8ms 内；初稿 v2 是 13.2ms 且同显 54/48。
这条和门禁里「效果卡的 total 不能谎报」是同一条精神。

另外两条是这一页独有的：

- **常驻感知层不是第二个 tab**，它是「这次运行为什么发生」的来源，所以做成运行的**出处条**
  （⑤ 展示它自己发起运行的样子，带「别再为这个提议」/「只在我问时」与本地唤醒预算 2/4）。
  唤醒判定刻意**留在纯代码里**：一个常驻 agent 的成本与烦人程度都由唤醒频率决定，把这个交给模型是不负责任的。
- **主动提案精确率**（68% · 留下 17 / 提出 25）常驻在界面上。未经请求就改用户的光标，
  错一次的代价远大于对十次；这个数字不摆出来，这套设计就没有自我约束。

### `10` 首轮走查修掉的五个缺陷（都是实测点出来的，不是静态阅读）

1. **核心内容全在折叠线以下**（同 `02` / `04` 踩过的坑）。第一版把 6 个 section 竖着堆在单列里，
   实测在真实默认窗口下**渲染证据、客观指标、效果程序三整块都看不见**，创作循环只露出 5 步里的 3 步。
   改法三条：从 `md`（960）起就分两列而不是等到 `lg`；「渲染证据 + 客观指标」合成一个「验证」
   （两个卡头 + 四层内边距白吃 ~76px，而它们本来就是同一件事）；「效果程序」可折叠，
   md 折起 / lg 展开，折起时卡头保留一行摘要，且用户手动开合过就不再替他决定。
2. **主操作要滚动才够得着**。候选就绪态右列约 560px、可视区只有 400px，「接受」落在折叠线以下。
   交付动作条改成钉在滚动区之外的 `shrink-0`（同 `06` 的底部操作条）。
3. **撤销没有重做**。`shell.js` 的 `doUndo` 只在撤销函数**有返回值**时才往 redo 栈里压，
   漏了这一步的后果是撤销之后 `⌘⇧Z` 是死的——而决策 #1 要求两者成对。
4. **「接受」在界面上没有痕迹**。原先只弹一个 toast、段落状态一点没变，
   于是撤销恢复的是与当前完全相同的状态——**一个看不出差别的撤销等于没有撤销**。
   现在接受会把段标成「已写入」，撤销/重做在它上面来回切。
5. **只有自动那条路径是死的**。舞台原先用 `requestAnimationFrame(play)` 自动播一遍，
   实测在页面不合成时 rAF **根本不触发**（手点「播放」却是好的）；同理 Web Animations 的
   时间线也靠帧推进，`finish` 永不触发，于是那一批粒子会停在首帧糊在舞台中心。
   改成 `setTimeout` + 零宽守卫 + 一个兜底清扫定时器。
   这类「自动路径死掉、手动路径正常」的缺陷与 `controls.js` 那条
   「共享层最没人验证的路径就是它自己的默认路径」是同一族。

## 走查中发现的、稿子自身的实现级教训（重构时同类问题会再出现）

0. **同一个 landmine 我踩了两次。** 迁到共享外壳后，`02` 和 `03` 各自残留一套页内 toast，
   `$('toastUndo')` 变成 `null` → 整段页面脚本从那一行起不再执行。第一次只修了 `03`，
   没有全稿排查，`02` 又以同样方式坏了两轮（滑块、预设、精确值输入全是死的）。
   **发现一个此类问题时，必须立刻全稿 grep 同一模式，而不是只修当前页。**
1. **迁移到共享外壳后，页面残留的自有 DOM 引用会静默炸掉整段脚本。** `03-app-rules.html` 里旧的页内 toast 被移到外壳后，`$('toastUndo')` 变成 `null`，`.addEventListener` 抛错——从那一行起本页所有绑定（行内控件、高级规则折叠、应用挑选浮层）全部没执行，而页面看起来是正常的。**教训：抽取共享层时要逐个检查页面对被移走 DOM 的引用，并且要验证「交互是否真的还能用」而不只是「页面是否渲染」。**
2. **批量文本替换必须断言命中。** 至少三次补丁打在了不存在的模式上、静默什么也没改
   （`03` 的分段控件绑定、`02` 的滑块监听）。另有一次正则删除切错了边界，留下
   `easingThumb` 等已删除标识符的引用，导致整段脚本语法错误——**改完要跑一次
   「内联脚本语法自检」**：把每个 `<script>` 的内容喂给 `new Function()`，能一次性抓出这类问题。
3. **Tailwind 会按 content 扫描裁剪 `@layer components`**，新增 HTML 后必须重新编译，否则自定义类和任意值类（如 `h-[318px]`）会被摇掉，表现为「高度归零、栅格失效」。
4. **`<script defer>` 会晚于内联脚本执行。** 库页一开始用 `defer` 引 `controls.js`，
   内联脚本先跑、`Ctl` 还未定义。共享层必须用阻塞式 `<script src>` 且放在使用它的脚本之前。
5. **顶层 `const` 不会挂到 `window`**，跨脚本自检时取不到，需显式 `window.Ctl = Ctl`。
6. **编译校验要看全部输出**：`tail -2` 曾把 `CssSyntaxError` 挡在视野外，导致 CSS 长时间是旧的。用 `grep -E "Done|error"`。
7. **可选链防不住 TDZ。** `sizeSlider?.set(v)` 看起来是在防「还没初始化」，但 `?.` 只防
   null/undefined；若 `sizeSlider` 是后面才 `const` 声明的，访问它会抛
   `ReferenceError: Cannot access 'X' before initialization`，整段脚本从那行起停掉。
   而 `Ctl.slider` 构造时就会同步跑一次 `paint() → onChange`，正好落在那个窗口里。
   **这是教训 #0 的第三次复发**——前两次是 DOM 引用，这次是绑定初始化顺序，症状完全一样：
   页面渲染正常、交互全死、控制台看起来干净。已由 `check-ui-spec.mjs` 的
   `optional-chain-before-init` 规则机械拦截。
8. **「页面渲染正常」永远不能当作验证结论。** 上面这条是靠**真的去点了一下底色切换按钮**
   才发现的：截图完全正常，DOM 结构完全正常，`typeof someFn` 也全是 `'function'`
   （函数声明会提升，所以它证明不了执行到过那里）。可靠的探针是**只在脚本末尾才会发生的副作用**，
   或者程序化调一次控件 API 看它在不在。
9. **门禁必须自测。** 两个 check 脚本都跑过「注入违规 → 确认报出对应 rule id → 还原」。
   一个从来没被验证过能失败的门禁，和没有门禁没区别。
   `classname-rebuild-with-layout` 这条规则第一版是**逐行**匹配的，自测立刻发现它抓不到
   真实写法——因为 `+ 动态部分` 常常换行写在下一行。不自测就会上线一条永远 PASS 的死规则。
11. **逐行正则会漏掉跨行语句。** 上面那条的具体形态：`el.className = '…'`（第一行）
   `+ MAP[k];`（第二行）。凡是判定「字面量后面有没有拼接」的规则，都必须整源扫描后再算行号。
13. **稿子必须对照真实代码盘一遍「有没有丢功能」。** 走查只能发现「稿子里画错的」，
   发现不了「稿子里没画的」。这轮丢掉的四个功能（列宽拖拽、卡片重置、卡片折叠、自动循环）
   全都在真实代码里工作着，但稿子里一个都没有——**光看稿子永远看不出来**。
   办法是拿真实组件的 prop / 导出名去 grep 稿子：`ResetCardButton` 16 处 → 稿子 0 处。
14. **同一个 `<script>` 块里没有下一块才定义的助手。** 我加分隔条时在第一个内联块里写了
   `$('colSplit')`，而 `$` 是在第二个块才 `const` 定义的 → `$ is not defined`，
   那一行之后的绑定全没执行，但布局预设按钮（绑定在它前面）照旧能用，
   于是表现成「预设有效、拖拽无效」这种极容易误判为「拖拽逻辑写错了」的样子。
15. **联动必须双向。** `05` 的拦截分布筛选在**开启**时顺带改了结果筛选，**取消**时没还原，
   于是留下一个粘住的筛选、看起来像数据丢了。凡是「打开 A 时顺手改 B」，
   都要同时写「关闭 A 时把 B 还原」，并且要考虑用户中途手动改过 B 的情况。
16. **「装不下」和「能滚」要分清。** 我一度把 06 提案列表判成缺陷（「6 条里 3 条被压在操作条下」），
   实际那个容器 `min-h-0 flex-1 overflow-y-auto` 工作正常、能滚 345px、第 5 条 op 滚一下就出来。
   `getBoundingClientRect()` 只告诉你元素在视口的哪儿，**不告诉你它是否可滚达**；
   判定截断要看祖先链上的 `overflowY` 与 `scrollHeight/clientHeight`。
10. **剥注释再做静态检查。** 稿子里到处是「这里原先 `$('toastUndo')` 变成 null」这类**讲述历史缺陷**
   的注释；不剥注释的话门禁会把说明文字当成真实代码报出来。一个会喊狼来了的门禁很快会被忽略——
   第一版 `check-ui-spec.mjs` 就报了 6 条这种假阳性。
17. **门禁不能按「文中提到了谁」来判断页面属于哪一类。** `viewport-breakpoint-in-shell`
   用 `/shell\.js/.test(source)` 认「这一页装了外壳吗」，而 `library/components.html`
   在正文里讨论 `shell.js` 的 toast 实现——于是它一次报了 **16 条**，
   而那一页根本不套外壳、`md:` / `lg:` 在那里完全正常。
   同一份脚本里其实早就有正确判据（`SHELL_TAG`，按 `<script src>` 标签认，
   注释写着「不能按文中出现 shell.js 认」），只是那条规则没跟着改。
   **一条按提到谁来判断的规则，会随着稿子写得越详细而越吵**，而越吵就越快被绕过。
   顺带一个坑：把 `SHELL_TAG` 挪到第一个使用点之前是必须的——`const` 不提升，
   留在下面会抛 TDZ ReferenceError（教训 #7 的同一族，只是这次发生在门禁自己身上）。
18. **存下来的几何值，从存下的那一刻就开始过期。** `library/components.html` 的卡片折叠
   第一版是「装载时量一次 `scrollHeight` 存进 `style.maxHeight`」。实测那次测量发生在
   预览窗格只有 355px 宽的时候，段落折成很多行、量到 **578px**；窗口变宽后内容其实只需要 78px。
   反方向才是真伤：在宽窗口量到 78px 之后收窄窗口，内容需要更多高度，
   于是**折叠过一次的卡片会把自己的内容裁掉一截，而且不报错**。
   改法不是「加个 resize 监听去重量」，而是**让展开态不持有任何像素值**（`max-height: none`），
   测量只用于动画的那一帧。这与门禁 `measured-geometry-without-viewportchange` 是同一族问题。
19. **探针必须先把窗口设成真实档位，再开始数。** 同一份「竖排单字」探针在默认预览窗格
   （实测 355×370）里数出 **57 处**，样本却是「通用组件库」「配置控件库」这种正常标题；
   把视口设成 960×680 之后是 **0**。这是 CLAUDE.md 记的「两次都是探针在说谎」的第三种形态——
   前两次是幂等性和时间点，这次是**测量环境**。
   同理，「与容器同色」的判据从 `<1.12` 收紧到 `<1.02`：1.12 会把 `slate-50` 这类
   **有意的浅色调**（骨架、行内代码底、chip）全算成违规，而真正的缺陷全部是 1.00。

### `03` 重做：状态从 DOM 搬进数据，并补齐三个 P0 缺口

上一轮把 `03` 判成「基本健康」。再走一遍发现那个结论只是**没点到**——
这一页的问题不在某个控件，在**状态存在 DOM 里**：哪一行有 `.hidden`、哪个
`.seg-item` 带 `seg-item-on` 就是真值，裁决条再反过来读 DOM 算结论。
`syncVerdict()` 当时已经要靠一个 `shown()` 过滤器绕开「隐藏的行还在 DOM 里」，
而只要再加一个筛选框，同一个坑立刻复发第二次——**筛选是视图关心的事，
绝不该改变裁决**，可 `shown()` 分不出「被原型状态藏起来」和「被搜索筛掉」。

已改成 `rules` / `advRules` 两个数组是真值，DOM 只是它的投影：`verdict()` 读数据，
`filter` 只发生在渲染里。这一类问题从根上不存在了。这轮修掉的：

| # | 缺陷 | 为什么它藏得住 |
| --- | --- | --- |
| 24 | **切到白名单后整个区块的语义翻转了，而标题、副标题、计数、行内控件都没翻** | 区块还叫「例外应用」（「例外」是相对默认行为定义的，模式一翻它就和内容互相矛盾），计数还是 `3`——**其中 2 条已经被这一页自己标成「白名单下无效」**。一个把空配置也算进去的计数，说的不是用户想知道的那个数。现在标题换成「允许的应用」、计数只算真正参与裁决的条目、差额如实分类为「另有 N 条无效 / M 条已暂停」（两者下一步动作完全不同，合成一个「N 条不生效」没用） |
| 25 | **白名单下每行的分段控件只是把「关闭」那一格隐藏掉** | 剩下一个**看起来没被按下的「启用」**：用户读不出当前状态，也不知道按下去会发生什么。现在整块换成静态的「已允许」标记 + 主题选择器 |
| 26 | **空操作的穿透只做了例外那一层，高级规则那一层照旧「决定」** | 白名单下会读出「效果已关闭 · 来自高级规则「\*演示模式\*」」，而真正关掉它的是默认行为。用户照这句去删那条高级规则，**删完效果依然不开**。顺带修正一处过粗的判断：黑名单下的「启用」**只有跟随全局时**才是空操作，「启用 + 指定主题」（微信 + 夕霞）确实改变了结果 |
| 27 | **添加应用浮层是第 5 处没走 `placePopover` 的浮层** | 它是 `absolute right-0 top-10`，而页头装在 `#pageScroll`（`overflow-y-auto`）里。往下滚一点再展开，浮层顶部被容器裁掉；`720×480` 档下 5 行里只看得见 2 行，**连它自己的「关闭」按钮都在窗口外**。而 `placePopover` 的注释里就写着「以后新增浮层只要走这里，就不会再踩」——**注释拦不住任何人**，已加门禁 `popover-not-portaled` |

| 29 | **每行的主题选择器是自己画的第 4 套假下拉**，无 handler、点了没反应，而且写死一句「跟随全局」 | **它从不说全局是哪一个**——而那正是这一页唯一会被问到的事。实测在侧栏把主题从「几何」切到「流光」，`03` 整页纹丝不动（同缺陷 19 的「同一个值在两处显示而只有一处会更新」）。现在用共享 `Ctl.select`，「跟随全局」右侧直读当前全局主题名；`shell.js` 补了 `activeTheme()` + `themechange` 事件 |

#### 这一批补的两个 P0 与一次自伤

`ux-rearchitecture-spec.md` 6.2 把「暂停、恢复、删除一条规则」并列为 P0，而稿子**只有删除**。
后果是「这条规则是不是它干的？」这个最常见的排查动作只有一条路：**删掉再看**——
而删掉会连主题选择一起丢，试完还得重建一遍。

- **暂停 ≠ 关闭**，不能合并：关闭是一种**结果**（这个应用里不要效果），
  暂停是对**规则本身**的开关（这条先别算，与它的结果无关）。白名单下「关闭」是空操作，
  而「暂停」在两种默认行为下都有意义。
- 行尾从「垃圾桶」换成 `⋯` 菜单（暂停/恢复 + 移除）。三个动作横排会把行挤爆——
  行里已经有分段控件和主题选择器；收进菜单反而把行尾控件从 2 个降到 1 个。
- 状态槽**只有一个**，永远回答同一个问题「这一行此刻为什么不起作用」，
  且**暂停优先于空操作**：暂停时它是不是空操作根本无从谈起（恢复了才知道）。
- **不给暂停 / 无效行加 `opacity`**：这些行的控件仍然可点（暂停期间照旧要能改配置、
  看清「恢复后会用哪套主题」），而「看着像禁用、其实能点」比没有视觉区分更糟。

**走查当场抓到我自己引入的一个缺陷，值得记下来**：提示文案说「设成「关闭」的 **1** 行是空配置」，
按下「移除这些空配置」却删掉 **2** 行——把用户暂停着的规则一起清了。
根因是我只在 `render()` 里排除了暂停，而那个 handler 自己又写了一遍 `rules.filter(isVoid)`。
**一个数出来的数和一个删下去的数由两处代码分别计算，就一定会有一天不一致。**
已收成唯一的 `voidRules()`，计数与批量操作共用。这与决策 #9「时间只有一个编辑面」同源。

另一条 ux 规格第 5 节的硬约束：**「普通流程不使用 `text-2xs` 承载必要信息」**，
而这一页原先用 `text-2xs`（11px）装的是：分段控件的段名、动作/命中徽标、规则的匹配模式、
`bundle id`、以及**裁决条那句全页最重要的结论**。已按「是结论还是补充说明」逐个判：
控件名、状态徽标、行内动作、规则内容、裁决结论全部提到 `text-xs`；
真正的补充说明（「按 Esc 可取消点选」「按 bundle id 记录」「列表来源」「搜索范围」）保留 `text-2xs`，
全页只剩 4 处。**`text-2xs` 与 `text-xs` 的 `line-height` 都是 `1rem`，所以行高零变化**，
代价只是宽度涨约 9%。`.seg-item` 是共享类（`01`/`04`/`05`/`library` 也用），
所以三档 × 五页机械对比过：**竖排单字 0、裁剪 0**，现存溢出在改前改后**逐项一致**
（`01` 的两处是 720×480 这个已知低于可用下限的档，`04` 是键盘舞台的浮动键帽，`05` 是等宽时间列），
其中没有一处含分段控件——用「把字号临时压回 11px 再数一遍」验的，不是靠看。

`exportTheme` / `deleteTheme`）。已在 `shell.js` 实现菜单，并把 `buildDeleteThemePlan` 的两条
约束直接编码进去（内置主题不可删、至少保留一个），否则实现时会做出一个「点了删除然后报错」的按钮。

清点结果已写进 `scripts/check-ui-spec.mjs` 的 `PARITY` 清单，**两个方向都会失败**：

- `parity-code-anchor-gone`：代码侧锚点消失 → 这条清单必须被**有意识地**删掉，而不是默默失配

这条门禁自测过：把 `自动重播` 和 `id: 'duplicate'` 各改坏一次，确认都能报出对应能力名。

### 第 1 批 A · 五个共享组件（已落地）

`PageHeader` / `EmptyState` / `Segmented` / `NumberField` / `Skeleton`，全部**接进了真实调用点**
（只加组件不接调用点等于囤库存，knip 会如实报 unused）：

| 组件 | 接入点 | 顺带修掉的问题 |
| --- | --- | --- |
| `PanelSkeleton` | `ThemeWorkbenchPage` 的 `DeferredPanelFallback` | 原本是居中 spinner，懒加载时整块面板看起来像空了、出现时还跳版 |
| `EmptyState` | `AppRulesPanel` 的空态 | 三种空态语义分开（`neutral` 本来没内容 / `filtered` 被筛掉了 / `blocked` 缺权限）——它们的**下一步动作完全不同** |

| `Segmented` | `KeyboardPanel` 的「显示模式」 | 原本是 `SmallSelect` + `options={["typed","physical"]}`，**界面上真的把英文枚举值显示给用户** |
| `NumberField` | 从 `CursorSkinStudio` 里的本地实现**提升**上来 | 见下 |

`NumberField` 修掉了一个真实的输入陷阱：原本每次 `onChange` 都立刻 clamp，
于是 `min=12` 时想输「50」根本输不进去——按下「5」就被 clamp 成 12，第二键变成 122。
现在编辑期间保留草稿字符串，**失焦或 Enter 才 clamp 并提交**，Esc 放弃。
空串/非数字视为放弃编辑保持原值（不能静默变成 min）。
判定逻辑抽成纯函数 `resolveNumberCommit` 以便单测——项目里没有 DOM 测试环境
（434 个测试全是纯逻辑），**没有为了测一个组件就擅自引入 testing-library + jsdom**。

### 第 1 批 B · 撤销栈 + 快捷键（已落地）

**这是删掉保存 / 脏状态模型的硬前置**：自动保存把「保存 / 丢弃」这个后悔手段拿掉了，
撤销栈是它唯一的替代品。顺序颠倒会有一段时间既没有保存按钮也没有撤销。

- 栈的语义在 `lib/undoStack.ts`（纯函数，11 条单测）：**按主题分桶**、**撤销与重做成对**、
  **连续同目标改动合并**。
- **合并不是优化而是必需**：`ControlSlider` 用的是 Radix `onValueChange`，拖动时每帧提交一次。
  实测一次拖拽（0→3）若不合并会产生 3 条记录，按一次 ⌘Z 只退回一帧；
  合并后一步退回 0。真机验证过这条。
- 记录点只有一个：`useThemeWorkbenchState` 里的 `updateCurrentTheme`。
  所有草稿改动（字段、预设、光标皮肤、键盘、AI 补丁）都从那个 updater 走，
  在唯一漏斗上记录，将来新加改动入口也不会忘记录。
- 键位表与「什么时候不该触发」在 `lib/shortcuts.ts`（19 条单测）。两条最容易写错的：
  **输入框里 ⌘Z 必须让给浏览器原生文本撤销**，**⌘1 必须能在输入框里打出「1」**。
- **⌘K / ⌘N 刻意没有注册**：命令面板在真实代码里还不存在，⌘N 的 composer 状态还私有在
  `ThemeLibrarySidebar` 里。注册一个没实现的键位会吃掉原生行为又什么都不做，比没有更糟。
- 撤销 / 重做在**两端工具栏都有可见按钮**（带动作名，如「撤销：左键单击」）。
  只有快捷键的功能等于隐藏功能——没人会去猜一个没有按钮的快捷键存在。
- `toast` 补了撤销动作位（决策 #7）。

顺带修掉一个 a11y 缺陷：`ThemeCard` 把整张卡包成 `<button>`，里面又有「重命名」`<button>`——
**button 套 button，HTML 无效、激活行为未定义、读屏器读不清**。
把 hover-only 改成常显之后这个嵌套更要紧了（内层按钮现在一直都在）。
改成「铺满卡片的选择按钮垫在内容下面」，实测嵌套按钮数 0、选卡与重命名都仍可用。

### `01` 结构重想：时间原先有两个编辑面

决策 #9 说「时间轴是时间的**唯一**编辑面：偏移、时长、缓动曲线、错峰都在这里；
卡片只管外观」。但稿子自己违反了这条——**决策 #9 点名的四样，时间轴和卡片各有一套**：

| 决策 #9 说归时间轴 | 时间轴确实有 | 卡片里**也**有（已移出） |
| --- | --- | --- |
| 偏移 | `off`（拖块体，可吸附到锚点） | `入场延迟` |
| 时长 | `dur`（拖块边缘） | `时长` ×2、`淡出时长` |
| 缓动曲线 | `curves` 每属性一条贝塞尔 | `入场缓动`、`出场缓动` |
| 错峰 | `repeat: {n, stagger}` | `错峰间隔` |

触发时间同样：README 说触发的节流窗 / 连击窗要和效果「放在同一把标尺上」，
时间轴的触发轨确实画了 `节流 60ms · 连击窗 900ms`，但那是**只读文本**，
真正能改的是触发行为卡里的输入框——**方向做反了：时间轴在显示，卡片在编辑。**

**这不只是不一致，是会说谎**：两个面编辑同一个值又不互相同步，谁最后动谁生效，
另一个照旧显示旧值。这正是决策 #9 存在的原因。

已改成：

- 卡片删掉 9 个时间字段（飘字 5、波纹 1、粒子 1、触发 2），
  卡片留下的就是纯外观（文案、字号、颜色、上浮距离、半径、线宽、数量、形状…）。
  「其余 N 项」计数与 `total` 一并跟着改了。
- 卡头加一枚**只读**时间 chip，点它跳到对应轨：抽屉收着会先展开、滚到该轨、闪一下
  （与 ⌘K 的 `revealField` 反向对称）。chip 文案直接读出时间关系，
  例如飘字是 `820ms · 波纹峰值 +40ms`、波纹是 `620ms · 跟随触发`。

**为什么是「删掉 + 跳转」而不是「两边双向同步」**：同步能修掉互相说谎，
但修不掉更根本的一条——**关系型时间没法用数字框表达**。
「飘字起点 = 波纹峰值 + 40ms」塞进输入框只能退化成绝对毫秒，
而那正是走查里已经踩过的坑（链接目标被关掉后固化成绝对时间）。

代价说清楚：**调一个时长多一次跳转**。换来的是时间只有一个地方能改；
而 chip 直接显示当前值，只看不改的场景零成本。

留给实现时注意的一点：**预设是跨越卡片与时间轴的**（套一个预设会同时写外观和时间），
所以预设 chip 仍然留在卡片上——它不是编辑面，是起点。

### 稿子的基准尺寸是错的：1440×892 vs 桌面真实的 960×680

外壳原先写死 `h-[892px] max-w-[1440px]`，而真实桌面端是
`width: 960, height: 680, minWidth: 720, minHeight: 480`（`src/desktop/main/workbench-window.ts`）。
**整套稿子是在一个比默认窗口宽 50%、高 31% 的尺寸上画的，而这个基准从没被核对过。**

后果不是「窄屏没适配」这种边缘问题，而是**所有基于尺寸的设计判断全部失真**。同一份 `01`：

| | 大屏 1440×892 | 桌面默认 960×680 | 桌面最小 720×480 |
| --- | --- | --- | --- |
| 时间轴轨道 | 684 | **204** | **2** |
| 舞台 | 408×253 | **224×41** | **131×2** |
| 配置列高 | 314 | 102 | **0** |

README 说把时间轴改成底部抽屉的全部理由是「原先挤在右列只有 ~400px 宽」，改完宣称 684px——
**684 只在 1440 下成立，默认窗口下是 204px，比它要取代的那个 400px 还窄一半。**
舞台同理：41px 高连一次文字上浮（54px）都装不下，而批评旧舞台 212px 的理由正是「装不下」。
还有一处自相矛盾：`07` 说「窄于 1200px 退化成两列」，而默认窗口是 960px——
**按这条策略用户默认就处在退化态**，永远见不到 `01` 整页围绕其设计的三列布局。

**最关键的发现：布局从来不会「坏」，它只是一路缩到没用。** 全套都是 `min-h-0 flex-1`，
所以窗口变小时永远不溢出、永远不裁切。把五个页面在两档尺寸下机械对比，
**新增溢出 0、新增过小元素 0**，只有 `05` 多一条文字截断——而舞台已经只有 224×41。
所以「装不下」不是溢出问题，是**内容的最小可用尺寸从来没被表达过**，
任何查溢出 / 查裁切的探针都抓不到它。

已改：

1. **基准换成桌面默认 960×680**，外壳加「窗口尺寸」切换条（桌面默认 / 大屏 1440×892 /
   桌面最小 720×480）。大屏档保留——它是这套设计最舒展时的样子，但它不能再当默认。
2. **舞台的最小尺寸按卡片上的真实取值算出来**（`stageMin()`）：波纹最大半径 120 → 直径 240、
   粒子扩散半径 96 → 直径 192、飘字上浮 64 + 字号 24 → 88，取最大并封顶 360。
   改卡片这里就跟着变，不是魔法数字。
3. **轨道最小宽 320px**，装不下就让 `#tlScroll` 横滚（DAW 的通行做法），标签列 `sticky` 钉住。
   **标尺行的栅格必须同步改成 `minmax(320px,1fr)`**——只改 `.tl-row` 不改标尺，
   README 已经修过一次的那个「刻度与色块错位、播放头偏 5px」会立刻复发，
   而且只在窄窗口下复发、宽窗口看不出来。三档实测栅格严格对齐。
4. **抽屉高度不再写死。** 原先 236/176 都是在 892px 外壳里挑的，换到 680px 窗口后仍占 225px、
   把舞台压到 41px。现在按可用高度夹取，舞台的最小值优先：实测 176/140/120 跟窗口走。
   **`drawerH`（用户拖出来的期望）与生效高度必须分开**——我第一版把夹取写回 `drawerH`，
   结果窗口一变小就把偏好永久改小、切回大屏也回不来（三档都停在 140，大屏本该 176）。
   「窗口小」是暂时约束，不该吃掉用户偏好。

**留给下一轮的：** `720×480` 下舞台 240 + 抽屉 120 + 外壳约 300 已超过 480px，
预览列会被裁切且没有滚动出路。这正是**应该提高 Electron `minWidth`/`minHeight`** 的证据——
按内容倒推：宽 ≈ 320 轨道 + 132 标签 + 间距 + 248 侧栏 ≈ **750px**；
高 ≈ 240 舞台 + 120 抽屉 + 300 外壳 ≈ **660px**。现在的 720×480 是拍出来的，低于可用下限。

#### 换成真实基准后逐页看图，`01` 的崩坏另有真因

基准换成 960×680 后按页截图走查（**必须真的看图**——机械探针在这一轮几乎什么都没查到：
五页在两档尺寸下「新增溢出 0、新增过小元素 0」，而 `01` 已经不能用了）：

| 页面 | 960×680 下的状况 |
| --- | --- |
| `01` 主题工作台 | **严重崩坏**：文字竖排单字、控件散落、只露 2 条轨 |
| `02` 光标皮肤 | 比例问题：舞台固定 380px 吃掉首屏，11 个状态一个看不见 |
| `04` 键盘动效 | 比例问题：屏幕预览占满首屏，配置控件全在折叠线以下 |
| `03` / `05` | 良好——都是单列 / 两列列表布局 |
| 共性 | 侧栏固定 248px，四条主题摘要**全部**被截断 |

规律：**单列列表页没问题，多列与含固定尺寸大预览的页面全崩**，因为它们的横纵预算都是按 1440×892 分的。

`01` 的真因不是我最初以为的「预览列太窄」，量出来是两条独立的：

1. **一个多余的 `</div>`**（第 95 行）。按 HTML5 解析算法它会**同时弹掉 `<section>` 和外面的预览列 `<div>`**，
   于是传输控件行与「本次输出」行掉出 section、成了 `#cols` 的额外 grid 子元素——
   实测 `#cols` 有 **5 个**子元素而不是 3 个，输出行被压到 **32px** 宽、三个标签被 `overflow-x-auto` 整个裁掉。
   **浏览器不报错，只是静默重排 DOM**：截图上只表现为「控件位置有点奇怪」，根因却在结构层。
   逐页看图找不出来——只有把 `#outputTags` 的父级链打出来、发现 `<section>` 不在链上才会露馅。
   已加门禁 `tag-balance`（自测过：注入这个多余标签，第一条就指向第 95 行并说明与第 60 行的 `<section>` 交叉）。
2. **布局预设的比例在窄窗口下把预览列压死。** 默认预设「配置优先」是 1.6 : 1，
   在 1440 下预览列还有约 458px，在 960 下只剩 **258px**，而舞台 `min-width` 就占 240。
   已改成**比例换算成像素后再夹一道**：预览列 ≥ 舞台最小宽 + 72，配置列 ≥ 340；
   两者都塞不进去（`720×480`）就改成**上下堆叠**，分隔条同时移出可达性树
   （留一个能聚焦、按了没反应的 separator 就是决策 #4 的反面）。

顺带修掉的比例问题，共同的判据是**竖排单字**：

- 竖排单字是「窄到没有任何可读性」的信号，任何时候都不该出现。装不下时的优先级是
  **横向滚动 > 换行 > 截断 > 竖排**——横滚要一个动作才能看全，竖排连读都读不了。
- 「本次输出」行禁掉换行、标签 `nowrap`、容器横滚；传输控件允许换行但每组 `shrink-0`。
- 卡头的让位顺序写明确了：**卡名（2–3 字）绝不让位**，让的是时间 chip（`truncate` + `title` 存全文）。
  反过来把卡名截成「飘..」比截断 chip 糟得多——卡名是这张卡的身份。
- **删掉卡头的「已启用」徽标**：它是同一个 bit 的**第三次编码**（决策 #3 的图标底色 + 同行的开关），
  而正是这个冗余徽标在真实宽度下和时间 chip 视觉重叠、两段文字叠在一起谁都读不清。
  删冗余编码比给冗余编码想办法让位更对。
- 删掉预览页头的「点一下即触发」：它和舞台内的 stageHint 说同一件事，且被压成**一个字**。
- 侧栏主题摘要改 `line-clamp-2`：125px 的框装 147px 的文字，四条摘要全被切掉最有辨识度的部分
  （粒子形状 / 波纹类型），四个主题看起来一模一样。侧栏纵向大片空余，折行代价接近零。
- 工作区导航从 `grid-cols-[minmax(0,1fr)_auto]` 改 `flex-wrap`：原先右侧工具组按 max-content 占位、
  把导航压到 0 再自行裁掉，720px 下表现为「主题工作台 / 光标皮肤 / 应」。
- **侧栏在�narrow于 860px 时自动折叠**。决策 #5「默认展开」是在 1440 基准上定的——
  248px 在 1440 下是 17%、在 720 下是 34%，同一个常量在两个尺寸下是两种设计。
  折叠态保留搜索入口，所以不等于失去入口。
- 抽屉与侧栏的自动折叠都**只在首次布局时决定**，用户亲手开合过就锁定。
  否则每次改窗口大小都把用户刚展开的东西收起来。

**`720×480` 仍然不可用**，且这不是能靠布局修好的：舞台 240 + 抽屉 120 + 外壳约 300 已超过 480。
按内容倒推的可用下限是宽 ≈ **750px**、高 ≈ **660px**。这是**提高 Electron `minWidth`/`minHeight` 的依据**，
但那属于真实代码，本轮只在稿子里留档，不改代码。

#### 系统性问题：22 处 Tailwind 视口断点，**没有一处按设计意图生效**

修 `02` / `04` 时挖出来的，比那两页本身更重要。

这些页面的内容都装在 `#mockWindow` 这个**固定尺寸**的模拟窗口里，而 `sm:` / `lg:` / `xl:`
响应的是**浏览器视口**——两者毫无关系，所以每一处要么恒真、要么恒假。最贵的两处，
恰好都是「本版重新设计的核心内容看不见」：

| 位置 | 后果 |
| --- | --- |
| `02` 的 `xl:grid-cols-[minmax(0,1fr)_360px]` | **从未生效** → 「11 个光标状态分 6 组」一直堆在 380px 舞台**下面**，真实默认窗口下首屏一个都看不见——而这正是 02 这一版重新设计的全部重点 |
| `04` 的同一处 | **从未生效** → 入场方向 / 字号 / 缩放 / 语义分层这些**主任务控件**全在折叠线以下，首屏只剩一块辅助用的屏幕预览 |
| 4 个页头的 `lg:flex-row` | 恒真（浏览器窗口 ≥1024）——碰巧对，但和模拟窗口无关 |
| 5 处 `sm:grid-cols-2` | 恒真（≥640 恒成立）→ 强行两列后把文字压成竖排单字 |

**断点写了却不按窗口生效，比不写更糟**：它让人以为窄窗口已经考虑过了。

已改成 `group-data-[w=sm|md|lg]/win:`，档位由 `shell.js` 的 `widthBucket()` 按**模拟窗口**宽度
写在 `#mockWindow[data-w]` 上。档位按内容能力切，不按整数好看：
`sm < 860`（侧栏自动折叠的同一条线，两列并排已无意义）／`md < 1200`（真实默认 960 落在这里，
次列用更窄的 280–300px）／`lg ≥ 1200`（稿子原来的设计基准）。
已加门禁 `viewport-breakpoint-in-shell`（自测过：把 `02` 的分档改回 `xl:`，能报出来）。

### 第三轮走查（2026-08-04）：预览在说谎，而所有视觉判断都建立在它上面

#### A5 · 预览只接了 4 个字段，其余全是硬编码

`renderFrame()` 里 `cardVal()` 只覆盖了 粒子·数量 / 粒子·扩散半径 / 波纹·最大半径 /
飘字·上浮距离 四个数值字段。**最显眼的三个全是写死的**：

| 卡片上写 | 舞台画 |
| --- | --- |
| 文案 `ZZZZ` | `Nice!`（字面量） |
| 字号 `34px` | `24px` |
| 颜色 `#F43F5E` | `#f59e0b` |

而 `cardVal` 上面那段注释当时就写着「三处各说各话，且改卡片对预览毫无影响」——
**上一轮只修了这四个数值，注释却写成了已经修完的样子。**

顺带查出：**「文案」是个死控件**。它走的是 `fieldRow` 最后那条兜底分支，
渲染成一个裸 `<input>`，**没有任何监听**——所以它从来没写回过 `f.value`。
这与 `shell.js` 侧栏搜索、`03` 浮层搜索框是同一族「画了控件没接线」。

修法与两条新约束：

- 每个可见字段都接上：飘字（文案/字号/颜色/上浮距离）、粒子（数量/形状/颜色/扩散半径/**重力**）、
  波纹（颜色/最大半径/**线宽**）。重力原先是写死的 `p0 * 24`，归一化成「重力 3 = 原来的 24px」，
  所以默认值下画面逐帧不变
- **形状几何收成唯一真值源**：`Ctl.SHAPE_PATH` 的 `fill` 从写死的 `#0f172a` 改成 `currentColor`，
  新增 `Ctl.shapeSvg(name, px, color)` 给舞台用。下拉缩略图与舞台粒子共用一份路径——
  两套形状代码必然有一天不一致
- **`PREVIEW_EXEMPT` 登记制**：接不了的字段（音效那 5 项）必须写明为什么，
  由门禁 `preview-fidelity` 机械执行。**缺席没有视觉痕迹**，靠人看永远看不出少接了哪个
- 文案要 `esc()`：它是用户输入而 `renderFrame` 走 innerHTML 拼串，输入一个 `<` 就把舞台撑坏，
  表现成「打了个字效果就没了」，最难往输入上归因
- 拖滑块时就重画舞台（决策 #8 的「可交互沙盒」本意）；提交路径统一走 `afterConfigChange()`
  单一漏斗（卡片 + 输出行 + 舞台最小尺寸 + 舞台画面四处一起更新）

**为什么它排在所有视觉/动效改动之前**：在一个忽略文案、字号、颜色的舞台上讨论动效，
结论不可信；而按这份稿子重构会把「预览不可信」这件事一起实现进去。

#### A1 · `chrome = 300` 是第三个魔法数，而它把 9 个播放控件整条盖住

上一轮把写死的 `236 / 176` 换成 `drawerMaxH()` 里的 `const chrome = 300`，
注释还逐项列着「标题栏 32 + 工作区导航 ~44 + …」。**那 300 是在 1440 下量的。**

实测 960×680：传输控件行会从 58px **折行成 94px**（倍速三档 + 循环区间 + 自动重播
在 427px 宽的列里放不下一行），真实 chrome ≈ 340。抽屉于是多放 40px，
而 `#stage` 带着 `min-height: 240px` 不肯让——它**溢出去盖住整条传输控件行**，
9 个按钮（播放/上一帧/下一帧/重播、1×/0.5×/0.25×、循环区间、自动重播）
`elementFromPoint` 全部返回 `#stage`。1440 正常，720 两态都坏。

讽刺的是「自动重播 + 间隔三档」正是 README 记的「稿子丢掉了真实代码里已经在工作的功能」
补回来的四项之一——补回了 DOM，默认窗口下够不着。

三处改动，每一处都换掉一个常量：

1. **`chromeH()` 实测相加**，等式写明：`drawerBody_max = main − 动作页签 − 抽屉标题行
   − 预览列非舞台部分 − stageMin`。传输控件行折行时它自己会变高，等式跟着变
2. **传输控件行必须单行**。原先 `flex-wrap` 的理由写着「窄列下允许换行（垂直代价可接受）」——
   实测那个代价一点都不可接受，多吃的 36px 正好把预算压穿。
   md/sm 档：倍速三档 → 一个 `Ctl.select`；循环区间 / 自动重播 → 图标按钮（`aria-label` + `title`）。
   **倍速有了第二个编辑面，所以同时建了 `setSpeed()` setter**——
   「同一个值在两处显示而只有一处会更新」是这份稿子出现最多次的缺陷，不等它复发
3. **抽屉打开时让出「本次输出」行**。纵向账：外壳 265 + 舞台 240 + 时间轴 120 = 625 > 主区 596，
   **差 29px，不是能靠削像素解决的**。唯一**有理由**让出的是「本次输出」行——
   抽屉打开时它是纯冗余，时间轴的轨道列表本身就是这一次输出哪几个效果，而且更准。
   这不是取舍，是消除重复；收起抽屉它就回来

外加两条兜底，都是踩过才写对的：

- **`enforceStageInvariant()`**：预算是上一帧量的，最终结果要再验一次。
  判据是「分给舞台的空间够不够 `stageMin()`」，**不是**「舞台 rect 有没有压到控件行 rect」——
  第一版写的是后者，而控件行是 `sticky bottom-0`，贴住之后它的 rect 是「视口里的位置」
  而不是「布局里的位置」，于是只要一滚就恒为「有重叠」，把 `overflowY` 永久钉在 auto 上。
  **sticky 元素的 rect 不能用来做布局判据。**
- 兜底纵滚用**内联样式**而不是切 class：`overflow-hidden` 与 `overflow-y-auto` 是同一层工具类，
  同时出现时谁生效取决于 CSS 里的先后（教训 #22 在 `hidden`/`flex` 上踩过同型，
  实测切完 class 后 computed 仍停在 auto）。
- 控件行 `sticky bottom-0`：兜底纵滚生效时（720×480 这种低于可用下限的档），
  舞台比预览列高，滚动会把控件行推出视口——实测滚到底后仍有 7 个按钮命中不到。
  **「能滚」也要真的滚得到才算数。**

三档 × 两态实测结果：

| | 舞台容器 | 舞台 | 抽屉体 | 点不到 | 兜底纵滚 |
| --- | --- | --- | --- | --- | --- |
| 1440 展开 | 366 | 354 | 176（用户偏好） | **0** | 否 |
| 1440 收起 | 542 | 530 | — | **0** | 否 |
| 960 展开 | 240（= 最小，正好） | 240 | 127 | **0** | 否 |
| 960 收起 | 330 | 318 | — | **0** | 否 |
| 720 展开 | 47 | 240 | 120 | **0** | 是 |
| 720 收起 | 130 | 240 | — | **0** | 是 |

`720×480` 仍靠兜底纵滚才能用，这与 README 之前的结论一致（按内容倒推的可用下限
≈ 宽 750 / 高 660），**且「舞台与时间轴同时展开」这个场景把高度下限推到约 710px**。
这一档的价值是当证据，不是当目标。

#### A2 · 主题只是个标签，而撤销栈假设它是数据

撤销栈已经**按主题分桶**（`historyByTheme`），也就是说这套设计的前提是
「每个主题有自己的编辑状态」。而 `01` 把 `CARDS` / `CH` / `TRIGGER` 放在模块作用域，
是**一份全局状态**。两个模型互相矛盾，实测出来是一条完整闭环：

1. 在「几何」里把波纹 涟漪 → 回声
2. 切到「流光」：**回声还在**，而撤销按钮变成「没有可撤销的改动」（disabled）
   → **用户看着一个自己改不回去的值**
3. 切回「几何」撤销 → 涟漪
4. 再切「流光」：**它也变回涟漪了**

而这一族缺陷 README 已经修过两次（`03` 缺陷 30 的主题选择器、`09` 缺陷 19 的状态行），
只是这一次错的那一处是最重要的一页，且**从没被这样测过**——
上一轮切主题的实测结论是「整页 textContent diff = 0」，当时被当成"没坏"。

- `shell.js` 新增 `themeState(themeId, factory)`（一个 Map + 懒初始化）与 `onThemeChange(fn)`
- `01` 的 `CARDS` / `CH` / `CH_BEFORE` / `CH_DEFAULT` / `TRIGGER` 全部改成指向桶，
  切主题时**换引用而不是复制内容**——桶里的东西必须留在原主题里
- **`chDefault` 与 `chBefore` 分开**：前者是这个主题的出厂默认（「重置为默认」的目标），
  后者是「我这一轮动手之前」（A/B 的目标）。README 已经为这个区别修过一次 A/B
- 每个主题给了**看得出区别的种子**（照侧栏那四条摘要写），并刻意让**时间**也有区别：
  实测总长 几何 1440 / 流光 1740 / 熔金 1080 / 夕霞 1920ms。
  没有区别的话「切主题」在界面上无法验证——修完和没修一模一样，
  这正是它上一次坏掉没被发现的原因
- 舞台同步跟着走（与 A5 的接缝）：几何=黑方块、流光=青圆点、熔金=金星形、夕霞=玫红钻石

三主题交叉实测：各自独立持有 文案 / 波纹预设，互不影响；在 A 改的值不出现在 B；
撤销跟着主题走；未动过的第三个主题保持种子值。

#### A3 · 「其余 N 项」是个折叠器，但它从来没有可折叠的内容

`groups` 原先**只有字段名字符串**，展开后渲染成一排静态 chip。实测两种状态下
`.ctl-row` 恒为 2、可交互元素恒为 17——**8 张卡都是**。也就是说决策 #2 说的
「其余收进『显示全部 N 项』」只做了「收进」，没做「显示」；按 README 自己的口径
（一套主题约 390 个配置决策），**绝大多数字段在稿子里没有任何编辑形态**，
而 ⌘K 号称能跳到它们。

- 新增 `GROUP_SPECS`（label → 类型/取值范围/选项），`materializeGroups()` 在种子里
  把分组字段物化成真字段对象，带 `group` 标记。常用字段与「其余项」现在是
  **同一批对象的两个视图**
- 新增 `toggle` 字段类型（渐变开关 / 启用拖尾），带 `role="switch"` + `aria-checked`
- 「其余 N 项」按钮补 `aria-expanded`（原先是 `null`）
- **计数与实际控件数同源**：实测八张卡 66 个字段与卡上的 `total`（1+19+7+5+17+5+5+7）
  逐项对齐。缺规格的 label 会 `console.warn` 而**不是静默跳过**——
  正因为不静默，`动画 · 颜色` 漏了规格当场就被计数暴露出来。
  「一个数出来的数和一个画下去的数由两处代码分别计算，就一定会有一天不一致」

#### A4 · ⌘K 的 55 个字段里 51 个落不到字段上

两个独立根因，都源自「按文本内容去 DOM 里猜」：

| # | 根因 | 后果 |
| --- | --- | --- |
| 1 | `hit?.closest('.ctl-row, .ctl-row-wide, .grid')` —— **`#cols` 自己带 `grid` 类** | 46 个字段把高亮环打在 `#cols`（898×341，整个配置区连 8 张卡）。**整块都闪 = 什么都没闪** |

#### 本轮我自己引入、当场抓到的六个（值得记，都是这份稿子的惯犯形态）

1. **`toast()` 把「应用到桌面」自己标成脏**——它捆了提示/撤销/标脏三件事，加第四件时立刻出事。已拆出 `{ draft: false }`。**一个函数默默替调用方决定语义，就一定会有一天决定错**
2. **`mountCardControls` 的 `[data-slider]` 选择器认领了宏观旋钮的滑块**（先跑并打 `data-mounted`），于是 `bindKnobs` 一个都没绑上。症状是**「读数动了、别处全不动」**，看起来极像旋钮的数学写错。已加 `:not([data-knob])`
3. **速度旋钮方向反了**：读数说更快（150%），时长从 620ms 变成 930ms。**一个方向反了的旋钮比没有旋钮更糟**

### 光标皮肤：从 2 个槽位重新设计成完整状态体系（`02`）

原先只有 2 个槽位（主皮肤 + 拖拽中），理由写在真值源注释里：桌面运行时只识别这两种。
但那是**当前能力**的限制，不是这套皮肤体系应有的样子——一套光标皮肤本来就该覆盖
文本、手指、滚动、精确选择等形态。所以稿子按**完整体系**设计，11 个状态分 6 组：

| 分组 | 状态 |
| --- | --- |
| 基础 | 普通（主皮肤，其他状态的继承源） |
| 文本 | 文本选择 |
| 指向 | 可点击、帮助 |
| 拖拽与滚动 | 可拖拽（张开手）、拖拽中（握拳）、滚动 |
| 精确操作 | 十字准星、缩放 |
| 状态反馈 | 忙碌、不可用 |

几个设计判断：

- **分组不是为了好看。** 11 个状态平铺是一堵墙，而它们天然分成几个「同一类形态」的族——
  用户配皮肤时是按族想的（「我要一套手型」），不是按字母序想的。
- **可达性如实标在每一行**：`现在生效`（当前运行时真能产出）/ `待系统能力`
  （配置会存下来，能力就绪后自动生效）。**必须标**，否则用户配了一堆以为坏了；
  但**也不能因此不给**，否则这套皮肤永远只能做两种形态。
  同一句解释只在分组头出现一次，不在 9 行里各重复一遍——重复即噪音。
- **继承是核心动作，不是附属选项。** 11 个状态不可能让人上传 11 张图，
  所以默认全部继承主皮肤，需要时逐个「派生」成独立素材，另给「全部派生」。
  每次切换都带撤销。
- **每个状态画成能认出来的形状**（I 型光标、张开手、握拳、准星、缩放箭头…），
  列表要读起来像「一套光标」，而不是一排文字配一排相同的方块。
- **`只看现在能生效的状态`** 开关：想立刻见效的人勾上就只剩 2 行，
  想设计完整套的人保持默认。默认展开全部——用户要的就是完整体系。
- 没有主皮肤时所有派生按钮禁用（没有继承源，派生是空操作）。

**桌面端要真正生效需要新增能力**，这一条还没做、也没有偷偷假装做了：
原生 helper（`native/macos/cursor-visibility-helper.c`）只能 `CGDisplayHideCursor`
隐藏/显示光标，**读不到系统光标形状**。可行路径是用已授权的辅助功能 API
`AXUIElementCopyElementAtPosition` 取指针下元素的 `AXRole` 反推状态
（`AXTextField`→文本、`AXLink`/`AXButton`→可点击、`AXScrollArea`→滚动）。
代价：AX 是同步跨进程调用，目标应用卡住时会阻塞到超时，**绝不能按 pointermove
频率跑**，必须「指针静止 ~100ms 才查 + 按位置缓存 + 硬超时」；而且 Electron / 游戏 /
Java 应用的 AX 树很差，覆盖率一定是部分的——这也是界面上必须保留
`待系统能力` 标记而不能改成「已支持」的原因。

### 二、同一份数据的 6 份拷贝，其中一份已经打架

| 数据 | 拷贝 |
| --- | --- |
| 缓动曲线 | `library/controls.html`（`[label, desc, pts]`）· `04:2143`（`[label, pts, desc]`，**元组顺序还不一样**）· `04:1413`（`name → CSS 字符串`） |
| 字体栈 | `library/controls.html` 的 `FONTS` · `04:2137` 的 `FAMILIES` · `04:1319` 的 `families`（舞台渲染用） |
| 形状几何 | `controls.js` 的 `SHAPE_PATH`（注释自称「唯一真值源」）· `library/controls.html` 的 `SHAPES`（**死代码，写死 `#0f172a`**，与那句声明直接矛盾） |

**缓动那份已经不一致了**：04 的下拉缩略图画 `[.22, 1, .36, 1.18]`，
真跑的动画是 `cubic-bezier(0.68,-0.55,0.27,1.55)`（先下冲、再过冲 55%）——
**缩略图画的曲线和真的跑的曲线是两条不同的曲线**，而界面上没有任何痕迹提示这件事。
这正是「一个数出来的数和一个画下去的形状由两处代码分别计算，就一定会有一天不一致」。

**而两处手写的「弹性 · 过冲 1.8%」也是错的**：按 `[.22,1,.36,1.18]` 实算峰值是 1.062（**6.2%**）。
所以过冲百分比现在由 `Ctl.overshoot(pts)` **算出来**，不再手写。
这个函数的自校验很关键：它对「弹跳」算出 **9.8%**，与原先手写正确的那一条逐位相同——
同一个函数同时复现了对的那条、纠正了错的那条，才说明它算的是同一件事。

顺带发现 `overshoot` 比原先的判据更准：原先用 `y1 > 1 || y2 > 1` 判过冲，
而 `[0.5, 1.3, 0.7, 0.9]` 的控制点超过 1、曲线峰值却只有 0.986——
**控制点越界不等于曲线过冲**，老判据会在这里说谎。

修完实测：04 的「弹性」下拉缩略图、说明文字「过冲 6.2%」、
`getAnimations()` 拿到的 `cubic-bezier(0.22, 1, 0.36, 1.18)` 三者同源（`match: true`）。

### 三、贝塞尔编辑器：钳位范围超出可见范围

上一版的映射是 `Y(v) = 100 - 80v - 10`，只给过冲留了 10 个单位（v ≤ 1.125），
而拖拽钳位放到 **1.6**。默认值 y1 = 1.56（「弹跳」的真实控制点）算出 `top: -34.8%`,
实测**拖柄浮在盒子上方 40px**——页面上多出一颗与任何容器都无关的黑点，
而它是这个控件最重要的那个手柄。

不变量定下来：**钳位范围 == 可见范围**，两者都由 `V_MIN` / `V_MAX` 一对常量导出，
没有第二处可以单独漂。盒高 104 → 160px，因为 0–1 那一段还得占到足够高度才读得出形状
（104px 时它只有 47px）。回归断言：默认值下两个拖柄都在盒内。

### 四、两处「今天恰好只有一个」的实现

- **单选卡**用全站 `querySelectorAll('[data-radio]')` 清空所有卡片。页面上只有一组时看不出问题，
  第二组一出现两组就会互相清空。作用域已收到最近的 `[role="radiogroup"]`。
- **快捷键捕获**（库页与 `07` 各一份）重复点击会**叠加 keydown 监听**——
  `onKey` 每次点击都新注册一个，而只有成功捕获或 esc 那一条路径会摘掉它。
  且点页面别处不退出捕获态，而在它退出之前用户按的**任何**键都会被 `preventDefault` 吞掉。
  现在捕获态是一个显式状态，三条退出路径（成功 / esc / 点外面）都走同一个 `stop()`。
  实测：点三次 → 只有一次捕获；按一次键 → 只写一次。
- 顺带修掉 07 的键帽渲染：`key.split('')` 逐字符出键帽，于是「⌘1–5」被切成四个键帽。
  **修饰键是单字符，主键不一定是**——`Ctl.keyParts` 只拆开头的修饰键，剩下整段算一个键。

### 五、可访问性：库页比界面页更差

`library/controls.html:159` 的色板**没有 role、没有 aria-checked**，选中态只由 className 表达，
而处理器用 `x.className = '…'` **整串覆盖**（教训 #15 那一族：打开时顺手改、关闭时没还原）。
而 `01-workbench.html:767` 手写的那份有 `role="radio"` + `aria-checked`，**是对的那份**。

**所以「库页是参照实现」这句话当时是反的：界面页比控件库正确。**

二维板 / 角度盘 / 曲线编辑器三者 `role` / `aria-label` / `tabindex` **皆无**，
键盘完全不可达、读屏无名——而那一节的标题写着「这三类是最该换掉的」。

二维板的键盘方案用**边缘轴轨**（底部 X、左侧 Y，各是一个 `role="slider"`），
而不是给中心圆点叠两个 `role="slider"`：两个 thumb 落在同一点时
`document.elementFromPoint` 在其中一个的中心返回的是另一个，**可达性探针会当场误报**，
而误报会淹掉真问题。轴轨顺带把「这个控件由两个分量组成」画出来了。

轴轨**满铺**而不是内缩：标记的百分比与圆点同一套坐标系，内缩会让两者差一个 inset，
「值一样、位置不一样」正是 02 校准图钉那一族。

### 六、布局：等高拉伸造成的卡内空白

`lg:grid-cols-2` 默认 `align-items: stretch`，矮卡片被拉到与同行高卡片齐平而内容不跟着长——
实测「数值输入」卡内空 **187px**、「下拉」卡内空 **326px**。
空白落在卡片**里面**时看起来像内容没加载完。加 `lg:items-start` 后卡片回到内容高度。

另外 6 处 `hint-note pl-[104px]` 魔数收成 `.ctl-hint`：104 = 92（标签列）+ 12（gap），

### 七、探针自己说了三次谎（都不是稿子的问题）

`此刻命中` 的覆盖缺口顺势闭合了：在①里把 Figma 例外改成「启用」，例外这一层成为空操作、
穿透到高级规则，于是徽标亮起且裁决条同步读出「来自高级规则「*演示模式*」」——
**整页七个状态实测自洽**（① / ②picker / ③first / ④denied / 高级接管 / 白名单+启用 / 回黑名单）。

**空操作在两个方向上是对称的**，这一点原先只做了一半：白名单下的「关闭」是空操作（已有
「白名单下无效」标记 + 「移除这些空配置」），而黑名单下的「启用」同样是空操作——
未列出的应用本来就已经是那个结果。裁决链现在两边都会穿透。

修 21 时我自己引入并当场实测抓到一个新缺陷，值得记下来：**裁决只能算真正显示着的规则。**
③ 首次进入把例外列表整段隐藏，但那些行还在 DOM 里，照旧去读就算出
「效果已关闭 · 来自例外应用「Figma」」——而首次进入的定义就是一条规则都还没有。
同一个 `shown()` 过滤顺带让「移除这些空配置」（给行加 `.hidden`）也被正确忽略。

两条新门禁规则，都做过「注入原始写法 → 确认报出对应 rule id → 还原」自测（教训 #9）：

- `interval-cleanup-after-early-return`：同一函数里既有 `setInterval` 又有 `clearInterval` 时，
  清理必须排在第一个 `return` 之前。收窄成「两者同时出现」是为了不误伤只 set 不 clear 的
  一次性定时器，也不误伤纯清理回调。
- `readout-convention-drift`：锁住 `mountSliders` 按 markup 的约定解析读数，防止有人把它改回纯选择器。

**没有**为「主题名写死」加门禁：实测全稿 `几何/流光/熔金/夕霞` 有 20+ 处合法出现
（THEMES 数据表、静态演示标记、诊断事件流、AI 风险文案），这条规则会喊狼来了（教训 #10）。

顺带补的四处（不是缺陷，是缺席——**缺席没有视觉痕迹**，走查点不到一个不存在的控件）：

- **例外列表没有筛选**，攒到 20 个应用只能靠滚。补了筛选框 + 「被筛掉了」空态（第三种空态语义），
  以及**缺权限 + 一条规则都没有**时的 `blocked` 空态（读不到最近用过的应用，下一步是去授权，
  不能摆一个空挑选器让人以为是坏了）。这一档可以靠「在 ④ 里把三行删掉」到达——
  **一个到不了的原型态等于没有这个原型态**（教训同 `10` 的 ⑦⑧ 拆分）。
- **`此刻命中` 原先没有可匹配的对象**：前台只有 bundle id、没有窗口标题，
  而那条规则匹配的是窗口标题。补了真实窗口标题（`季度复盘 — 演示模式`）并显示在裁决条上，
  于是通配符命中这件事**可以被验证**，不再是一枚写死的徽标。
- **只有一条高级规则时，「这里的规则有顺序」无法验证**：顺序、拖拽排序、「被上面的规则挡住」
  三件事全都看不见。改成两条**都命中当前前台**的规则，换一次顺序命中的那条就换人、裁决条同步变。
  排序同时给方向键（决策 #4 的同一条精神：操作不得只在某一种输入方式下可达）。
- **裁决条右侧那句「实时反映规则引擎的裁决结果」是关于界面自己的话**，占掉近半条宽度、
  对用户零价值。换成「为什么？」→ 诊断面板。

另有两条结构性改动，是上面十条的共同前提：

1. **状态从 DOM 搬进数据。** 这一页原先把状态存在 DOM 里（哪个 `.seg-item` 带 `seg-item-on`、
   哪一行有 `.hidden`），裁决条再反过来读 DOM。上一轮为此加了个 `shown()` 过滤器，
   绕开「③ 首次进入把列表藏起来但行还在 DOM 里」的问题。**而加了筛选之后同一个坑会立刻复发第二次**：
   被搜索框筛掉的行也是隐藏的，而**筛选是视图关心的事，绝不该改变裁决**——`shown()` 分不出这两种隐藏。
   现在 `rules` / `advRules` 是真值源、DOM 只是投影，filter 只发生在渲染里，这类问题从根上不存在。
   实测：筛掉 Figma 之后裁决条照旧正确读出「来自例外应用「Figma」」。
2. **「首次进入」是数据上的空**（`rules = []`），不是把已有行藏起来。于是缺陷 23
   （首次进入摆着一条存量高级规则）不需要 `data-show` 去修，它不可能发生；
   而高级规则卡仍然显示、计数 0、折叠——**能被发现，但不假装有内容**。

新增教训：

20. **一个补丁修掉的是症状还是机制，要看它能不能防住同一个坑的第二次。** `shown()` 那个
    DOM 过滤器确实修好了「首次进入读到幽灵规则」，实测也通过了。但它是按「元素是否隐藏」
    判定的，而隐藏有两种语义（这条规则不存在 / 这条规则被筛掉了），第二种一出现它立刻失效。
    **把状态搬进数据不是重构洁癖，它是让第二次不可能发生。**
21. **只剩一格的分段控件不是分段控件。** 「隐藏掉不适用的那一格」看起来是个安全的联动，
    实测出来的却是「一个没被按下的按钮」——状态与可用动作同时消失了。
    模式翻转时该换的是**整块的语义**（标题、控件形态、计数口径），不是藏掉其中一格。
22. **`hidden` 与 `flex` 同时写在 class 里靠顺序决胜是不可靠的**（同一层 display 工具类）。
    要 flex 布局的浮层必须成对开合 `hidden` / `flex`，和 `deniedNote` / `whiteNote` 一样。

## 内容信号层（能力分档）

> 2026-08-04 从 `CONTENT-SIGNALS.md` 合并进来（该文件开头自己请求过这件事，
> 当时 README 正被另一个会话改着）。这一节决定**这个产品最终能做到什么**，
> 比任何界面细节都更靠上：所有效果只能锚在它列出的信号上。
> 表达方式已按 `DECISIONS.md` 裁决 4 改成「能力包」——逐行贴「待系统能力」徽标
> 会让产品看起来到处发灰，而且那些灰看起来是永久的。

### 为什么需要这一层

桌面运行时能拿到的信息只有四样：指针 `x/y`、按键位掩码、`deltaY`、`keycode`，
加上前台应用的 `owner.name / bundleId / title`。所以所有效果只能锚在**指针位置**
或**屏幕边缘**。运行时唯一已有的「内容关系」是 `originMapping: keyboardLayout`
——按哪个键决定飘字的横向位置，仅此一处。

而稿子已经在两个地方**隐含承诺**了这一层，只是没被当成待建能力登记：

1. `05-diagnostics.html:192-204` 每组事件都带 `target`（`canvas` / `sidebar` / `slide`），
   「最近一次触发」详情第五行就是 **`命中目标`**。桌面运行时没有这个字段——
   `src/desktop/renderer/engine/trigger-handlers.ts:68` 的注释写得很直白：
   「桌面 CursorEvent 没有 target；扩展端调用方可在外层包装时塞入。」
2. `02-cursor-skin.html` 的 11 个光标状态里 9 个标着 `待系统能力`，
   而它们要靠的正是 AX 元素查询。

好消息是接缝已经存在：`src/shared/effect-runtime/action-trigger-pipeline.ts` 有
`target: unknown`(14 行)、`describeTarget?()`(46 行)、`resolveCursorStateId(target)`(36 行)、
`matchesTriggerZone(target, …)`。扩展端塞 DOM element，桌面端恒塞 `undefined`。
**接内容信号不需要改管线形状**，只要在桌面端给这条缝接一个 provider。

### 能力分档（按成本，不按好看）

| 档 | 需要什么 | 能做的玩法 |
| --- | --- | --- |
| 0 · 零新能力 | keydown 的 timestamp、deltaY、`clipboard.availableFormats()` | 打字节奏调制、语义键升级（退格反吸／回车扫光／空格词爆）、剪贴板格式反馈、滚轮惯性拖尾 |
| 1 · 窗口几何 | `get-windows` 的返回值里**已经有** `bounds`（`index.d.ts:54`），只是 `ActiveWindowSnapshot` 只取了 owner/title/processName，把它丢了。补回来即可 | 效果锚到前台窗口、效果被窗口边界裁剪／反弹、切窗过场 |
| 2 · AX 元素 | `AXUIElementCopyElementAtPosition` → `AXRole` + `AXFrame`。**权限本来就有**（uiohook 就要辅助功能） | hover 磁场光晕、按角色分流效果、`02` 的 9 个光标状态、诊断的「命中目标」 |
| 3 · AX 插入点 | focused element + `AXSelectedTextRange` + `AXBoundsForRange` | 插入点锚点打字动效、选区扫光 |
| 4 · 屏幕取色 | 小 rect 取色（**唯一需要新增屏幕录制权限**的一档；`active-window.ts:37` 现在显式关着它） | 效果自动取周围色调／自动对比色 |

两条必须写死的纪律：

- **AX 是同步跨进程调用**，目标应用卡住时会阻塞到超时。绝不能按 pointermove 频率跑：
  指针静止 ~100ms 才查 + 按位置缓存 + 硬超时。磁场光晕要跟手和这条冲突，
  折中是「静止时查一次拿到 `AXFrame`，光晕在该 rect 内跟手插值，指针移出 rect 才重新查」。
- **插入点不要轮询**。用 `AXObserver` 订阅 `kAXSelectedTextChangedNotification` /
  `kAXFocusedUIElementChangedNotification`，keydown 直接用缓存的 caret rect，
  每次击键的 AX 调用是 0。

隐私红线：caret 位置、选中文本这类信号**不进诊断日志、不送 AI**。
README 已为应用名定了「默认脱敏成『某应用』」，选中文本比应用名敏感一个量级，
应该是直接不采集而不是脱敏。`07-settings.html` 的「输入」组已经有三条守卫可以挂靠
（输入法组字期间不显示、忽略密码框与安全输入、全屏应用中暂停）。

平台范围：Windows 没有 AX 对等物（对应 `IUIAutomation`），所以档 2／3 是

### 本轮已落地（`04-keyboard.html`）

#### 锚点（新增能力面）

右栏新增「锚点」一节，三档用 `mode-card`（沿用 `03` 默认行为的单选卡），
每档带 `02` 那套两档可达性徽标——**「待系统能力」必须选之前就看得见**，
所以没用分段控件（那个只有选中后才看得到该档状态）。

| 档 | 徽标 | 依据 |
| --- | --- | --- |
| 屏幕 | 现在生效 | 现状 |
| 前台窗口 | 现在生效 | `bounds` 已在 `get-windows` 返回值里 |
| 文字插入点 | 待系统能力 | 需要 AX；覆盖率必然是部分的 |

实现要点：

- **三档统一成一个矩形** `anchorBox()`，位置公式只写一份。插入点是**零尺寸的框**——
  `A.x + A.w * offset` 在 `w=0` 时就等于 `A.x`，于是「键位散开」「水平偏移」这些
  按比例算的项自动失效，**不需要为 caret 写特例分支**。少一个分支就少一处将来会忘记同步的地方。
- 几何一律 `getBoundingClientRect()` 实测，不写死常量（README 教训：播放头当初就是依赖常量偏了 5px）。
- 拖拽换算回**锚点框内**的归一化偏移。用屏幕算的话，窗口锚点下拖到窗口中央会存成 0.5，
  而 0.5 是相对窗口的——换个窗口大小就全跑了。归一化的参照系必须和读取时一致。
- 插入点档**不加抖动**：这一档的全部意义就是精确出现在打字位置，抖开就退化成又一个随机飘字。
- 三档的 note 都必须说清**取不到时会怎样**。「静默不出效果」是这类功能最差的失败方式。

#### 调制（原「输入节奏加成」）

原先是「显示内容 · 决定按下的键显示成什么」组里的一个**没有说明文字的裸开关**，
和「显示单独修饰键」「强制大写」并列。两个问题：

1. **分组错了**——节奏跟「显示成什么」无关，它是强度调制。
2. **只有开关没有量**——`derive()` 里其实已经按连击级别在改 scale／opacity／glow
   三个属性（+3.5%/级、+2/级、≥3 级点亮发光），但界面上一个数都不给。

拆成独立一节并**移到左列**放在「语义分层」下面：两者是同一族（都是「打的什么 → 多强」），
而右栏原本已有 5 节、内容高度是左列的 1.7 倍。移动后 1198 : 1696（原 1198 : ~2000）。

暴露出来的是：强度滑块（100% = 现有系数）、三个作用目标可独立关、
以及「当前档位」实时读数（`3 级 · 字号 +10.5% · 不透明度 +6 · 发光`）。
三个目标全关时当场说「调制开着但不会有任何变化」——
这类「开了等于没开」的状态必须说出来（走查里同一类问题出现过：白名单下的「关闭」）。

### 逐项走查后修掉的（当产品经理和用户各走一遍）

前四条是这一页原有或我新引入的**真缺陷**，第五条是把已有的坏行为暴露出来后不得不修的。

#### 1. 页内 toast 覆盖外壳的 → 整条撤销链在这一页失效（**最严重，且是既有问题**）

`04` 原先自带 `function toast(text, before)`，同名覆盖了 `shell.js` 的全局
`toast(text, undo)`。实测后果：改动三次，工具栏「撤销」仍写「没有可撤销的改动」，
⌘Z 毫无反应，「已保存」从不闪「保存中」。

也就是**决策 #1「自动保存 + 撤销，全站统一，⌘Z 有历史栈」在这一页整条失效**——
而自动保存把「保存 / 丢弃」这个后悔手段拿掉了，撤销栈是它唯一的替代品。

这是 README 教训 #0 的又一次复发：迁到共享外壳后页面残留自有实现。当时扫了 `02` 和 `03`，
**漏了 `04`**。全稿重新扫过：`07/08/09` 也有本地 toast，但那三页刻意不加载 `shell.js`，属于正确情形；
`04` 是唯一一个装了外壳还留着本地 toast 的工作区页。

修法：删掉页内实现，加 `snap(before)` 把「cfg 快照」适配成外壳要的 undo 函数
（外壳约定「撤销函数返回重做函数，两者成对」），16 处调用点改走 `commit(text, before)`。
顺带补上**拖拽的撤销**——原先拖停留位置只报文案不带快照，
「位置」是这一页唯一撤销不了的改动。

#### 2. 插入点 + 雨滴退化成 40px 抽动（我引入的）

雨滴的行程原本是「贯穿锚点框」= `A.h + 两个字高`。屏幕锚点 401px、窗口锚点 257px 都读得出坠落；
插入点是**零尺寸框**，`A.h=0` → 行程只剩 `fontSize*2` ≈ 40px。而且这个组合下
`restField` 被 raindrop 分支藏起来，用户连一个距离控件都没有。

而「雨滴坠落」是四个预设之一，撞上的概率不低。

修法：零尺寸框下雨滴行程改由「坠落距离」（复用 `bounceHeight`）给出，
并让 `restField` 在这个组合下保持可见、标签改成「坠落距离」。实测 40px → 69px 且随滑块可调。

#### 3. 语义分层的「快捷键居中」被锚点吞掉（我引入的）

`derive()` 给快捷键档强制 `originMapping=center` + `offset 0.5/0.5`，意图是快捷键居中显示——
这是语义分层给快捷键用的**主要区分通道**。但插入点锚点下零尺寸框把居中吞掉了：
实测 ⌘K 和普通字符都落在 `x=428`，位置完全一样，「打字和快捷键一眼能分开」这句话就不成立了。

修法：**快捷键覆盖锚点**——base 锚点是插入点时，快捷键退回窗口锚点
（仍比屏幕贴近上下文，又不会跟正文混在一起）。实测 ⌘K 落到窗口中心 346、普通字符仍在 428。
并且这条规则写到界面上（快捷键那行图例在插入点锚点下改成「居中于窗口（不跟插入点）」）——
只写在代码里的话，用户会看到「我选了插入点，⌘K 却跑到窗口中间」而无从解释。

#### 4. 可达性徽标在缺权限态下谎报（我引入的）

原先徽标是静态的，于是「④ 缺少辅助功能权限」态下「前台窗口 · 现在生效」照旧显示——
而没有辅助功能权限时 `get-windows` 直接返回 `authorized: false`，根本拿不到窗口。
**新用户第一眼落地的正是这个状态。**

根因是一个徽标被要求承担两件事：**能力档位**（这个功能建好了吗）和**当前可用性**（此刻能用吗）。
这与规格第 5 节「权限错误、数据为空、当前未命中、保存失败是不同状态，不混用同一警告卡」同一条。

修法：加第三档 `需要权限`（amber），由 `reachOf()` 按权限态动态解析；
缺权限时 note 换成回落说明。同时让缺权限原型态**默认选中「前台窗口」**——
原先四个原型态没有一个会选到屏幕以外的锚点，走查者点完四个态永远看不到这两档，
和 README 记过的「`03` 的『此刻命中』徽标从没被演示过」是同一类漏洞。

#### 5. 按住一个键不放会把节奏档位刷满（既有行为，被我暴露出来）

实测按住 A 让它自动重复六次，「当前档位」一路爬到 5 级。而这一节自己写着
「打字越快，效果越强」——按住不放并不是打得快，这既是作弊入口，也让「节奏」名不副实。
`typingCombo` 原先只是个布尔开关，这个行为一直在，只是没人看得见。

修法：自动重复不推进档位（也不清零——按住不该把已攒的节奏抹掉）。
判据用 `KeyboardEvent.repeat` 而不是时间阈值：真实的双字母（hello 里的 ll）间隔也很短，
靠 30~60ms 阈值会把正常打字误判成按住。实测三种情形分别为
按住不放恒 0 级、正常打字 1→5 级、真实双字母正常计入 1 级。
原生侧 uiohook 没有 repeat 字段，但「同一 keycode 期间没有夹 keyup」是等价判据。

#### 6. 语义分层：300px 的说明书换一个布尔，且系数有四份真值

走查时被问「这个模块有什么用吗」，拆开验的结果：

**真在工作的三件事**——右上开关确实改行为；按键时对应那一行会闪（实测 `⌃K` → `shortcut`
行 `legend-row-hit` 亮起），这是它最有价值的部分，回答「刚才那一下被判成了哪一类」；
四个样张按相对大小渲染。配合插入点锚点后「分类可见」更重要了——快捷键要覆盖锚点跑到窗口中间，
用户必须能看出分类，否则那个位置跳变无法解释。

**但四行完全只读**：实测 click 后 `className` 无任何变化、`tabIndex < 0`、零控件。
默认窗口下约 300px 的左列空间，只换来右上一个布尔；它描述的四组数字用户一个都改不了，
不喜欢「快捷键放大 18%」只能整段关掉。而**旁边的「调制」是可调的**——
两个相邻模块一个能调一个不能调，这个不对称本身就是设计缺陷。

**而且系数散在四处**：`derive()` 的硬编码、`syncAll` 的 `rel` 预览表、
HTML 图例里写死的「放大 18% / 缩小 28% / 略大 8%」、以及我加锚点时那句动态文案里又抄了一遍。
**已经漂了一处**：修饰键样张不透明度写死 `.62`，而 `derive()` 实算 `max(45, 90×0.72)=65` → `.65`。

修法：

- 建 `SEMANTIC` 表作为**唯一真值源**（kind / 样张 / size / dur / opa / center）。
  `opa` 的两种算子如实保留（快捷键与特殊键是加法、修饰键是乘法），
  不为「统一好看」并成一种——那会静默改变现有效果。
- 加**每类强度档**：关闭 / 克制 / 标准 / 明显。强度只缩放「偏离基准的量」，
  所以 `1 = 现有系数分毫不差`（实测重构后 shortcut 仍是 1.18 / 648ms / 98，
  modifier 0.72 / 495ms / 65，special 1.08 / 738ms / 94，与重构前逐位相同），
  `0` 则完全等于字符基准、连「居中」这条位置通道也一并让掉。
- 行内说明、样张大小、样张不透明度、下拉当前值**全部从表算**，四份真值收敛成一份，
  `.62/.65` 的漂移随之消失。
- 关掉语义分层时三个下拉真 `disabled`，说明文案换成「语义分层已关闭，四类按键一视同仁」。

**强度用扁平字段 `semShortcut / semModifier / semSpecial`，刻意不用嵌套对象**：
这一页到处是 `{ ...cfg }` / `{ ...DEFAULTS }` 浅拷贝（`snap`、预设、原型态、恢复默认都是），
嵌套对象会被这些浅拷贝共享同一个引用——改一次 cfg 会顺带污染 `DEFAULTS`，
而 `snap()` 存的「改动前快照」也指向同一个对象，撤销会退化成空操作。
实测改动后 `DEFAULTS` 三个字段仍为 1。

### 顺带发现的真实代码缺陷（不在本轮改动范围内）

`src/shared/effect-runtime/runtime-config.ts:177-182` 的 `matchesTriggerZone` 已经实现了
六种**内容型**区域判定，全部走 `asElement(target)?.closest()`：

```
按钮和链接 / 可交互元素 / 空白区域 / 内容卡片 / 仅向上滚动 / 仅向下滚动
```

桌面端 `target` 恒为 `undefined` → `element` 为 `null`，于是：

- 「仅按钮和链接」「全部可交互元素」「可交互元素」「内容卡片」→ **恒 false，动作静默永不触发**
- 「空白区域」→ 恒 true，无条件触发
- 两个滚轮方向 → 正常（`deltaY` 桌面端有）

而 `TriggerBehaviorCard.tsx:28` **没有平台过滤**，桌面 Workbench 的「作用范围」下拉里
这些选项全都在。三个附带事实：

1. `src/desktop/renderer/engine/types.ts:100` 的注释写着「桌面端无 DOM target/event 时返回 true」，
   **和 shared 实现的实际行为相反**。
2. 五个桌面默认值（`当前页面可点击区域` / `右键菜单前` / `双击命中区域` / `按住后释放` /
   `向上 / 向下滚轮`）恰好都不匹配任何 `includes` 模式，全部 fall through 到 `matched = true`
   ——所以默认配置是**碰巧**正常的，这也是它一直没被发现的原因。
3. 稿子把三个选项换成了 `整屏` / `中心区域` / `边缘`，这三个字符串在 matcher 里
   同样一个都不匹配、全部恒 true。方向我认为是对的（桌面没有 DOM，屏幕区域才是诚实的桌面语义），
   但稿子没有任何地方说明这是一次**语义替换**，也没说扩展端要保留 DOM 语义。
   按稿子实现会得到两个结果之一：`中心区域`/`边缘` 是死控件，或者扩展端的内容区域被一起删掉。

建议：修的时候一并加一条门禁规则——「下拉里出现 matcher 不认识的 zone 字符串」就报错。
这和 `unimplemented-field` 锁 `trail`/`splash` 是同一类。
