# 决策裁决表

> **这份文件解决一件事：重构的人会同时读到两份互相矛盾的「已定稿」规格。**
>
> `docs/ux-rearchitecture-spec.md` 开头写「信息架构与交互原则已定稿」，
> `README.md` 写「已定的产品决策（重构必须遵守）」。两份在 8 处直接对立，
> 而稿子每次都实现了 README 那一份，**反转从未被记录**——于是 ux 规格的
> 验收指标（§9）还在为一个已经不存在的模型服务。
>
> 冲突以本文件为准。改变本文件里任何一条裁决，必须在这里改，而不是在稿子里静默偏离。

阅读顺序：`DECISIONS.md`（本文，裁决） → `README.md`（稿子怎么画的、走查记录）
→ `ux-rearchitecture-spec.md`（信息架构与任务流的原始论证，仍然有效的部分）。

## 1 · 保存模型：三层，不是二选一

**冲突双方**

- ux 规格 §4.2/§4.3：页面固定保存栏「保存更改 / 放弃更改」，`DirtyState = { global, themes }`，
  规则编辑器的提交按钮叫「完成」而不是「保存」；§9 验收指标「用户不会把『完成』误认为已经持久化」。
- README 决策 #1：**自动保存 + 撤销**，删掉保存按钮、脏状态标记、切主题时的保存/丢弃对话框。

**稿子现状**：实现了 README #1，页头是「✓ 已保存」。ux §9 那条验收指标无处可验。

**裁决**：三件事被混成了一件，拆开。

| 层 | 语义 | 形态 |
| --- | --- | --- |
| 参数改动（效果字段、时间轴、皮肤、键盘） | 自动落**草稿** | 无保存按钮，页头「草稿已存」+ 撤销栈 |
| 草稿 → **运行时** | 需要一次显式动作 | 「应用到桌面」/「恢复已应用版本」 |
| 对象类改动（一条规则、一个新主题） | **局部编辑事务** | 「完成」写入草稿，≠ 持久化到运行时 |

**理由**：README #1 删掉「保存到磁盘的焦虑」删对了，但它连带删掉了**「发布到运行时」这个开关**，
而这两件事在桌面端完全不同——桌面端的「编辑」就是在实时改变你此刻正在用的桌面：
演示中拖一下「粒子数量」，满屏真的多出粒子。这不是保存模型问题，是运行态与编辑态没有分开。

兜底手段也不够撑起「撤销是唯一的后悔手段」：真实代码
`src/app/pages/theme-workbench/lib/undoStack.ts:23` 的 `UNDO_MAX_DEPTH = 40`，
且是内存态、不跨重启。

第三层保留 ux §4.1 的理由很具体：**一条填了一半的规则不该边填边生效**。
README #1 把这一层一并删掉了，那是删错的部分。

**同时废弃**：ux §4.2 的「页面固定保存栏」、§4.3 的 `DirtyState` 类型、
§9 里关于「保存更改」的验收条目。§4.4 的迁移约束（主题导航不隐式改写 `activeThemeId`、
全局启用不重建整份配置）**仍然有效**，而且第 2 层让它更容易做对。

## 2 · 导航信息架构：采纳 ux §3 的意图分组

**冲突双方**

- ux §3：一级导航按意图分三组——**个性化**（主题与效果 / 光标皮肤 / 键盘反馈）、
  **自动化**（应用规则）、**系统**（诊断与性能）；且「主题侧栏只在个性化分组中显示」
  「进入自动化或系统时，主内容获得完整页面宽度」。
- 稿子：5 个等权平铺 tab，`shell.js` 在 6 个页面全部加载，**03 应用规则和 05 诊断面板上主题轨照旧占位**。

**裁决**：采纳 ux §3。**但不合并页面文件**——`01`/`02`/`04` 仍是三个独立稿子，
只是在导航上归入同一组。

**理由**：分组的收益是作用域清晰（见裁决 3），这个收益不需要合并文件就能拿到；
而合并会让 `01` 这个已经承载全部 P0 缺陷的页面更重。
「工作台太像 DAW」这个问题也不该由合并解决——裁决 12 试过用宏观旋钮层解决它，
已被推翻（见该条的推翻记录）。**问题仍然悬着，但合并不是它的答案。**

**落地约束**：进入自动化/系统组时，必须同时隐藏**主题侧栏、撤销/重做、「已保存」**——
它们三个都是"当前主题"这个作用域的产物，留任何一个都会重新制造裁决 3 要消掉的歧义。

## 3 · 作用域标签：从 0 处变成必填

**现状**：ux §2 要求每页显示「正在编辑：主题名」或「全局设置」。
全稿 `正在编辑` **0 处**。

**裁决**：采纳。每个工作区页必须有作用域槽，由 P4 的门禁 `scope-slot-missing` 锁住。

标记用 **`data-scope-slot`**，不是本条原先写的 `data-scope`（2026-08-05 改）：
`05` 的「域筛选」按钮已经占用了 `data-scope`（`data-scope="audio"` / `"pointer"` …），
按 `data-scope` 查会让 05 **靠一排筛选按钮假装通过**门禁。
槽位本身由共享外壳提供（`shell.js` 的 `#scopeSlot`），所以门禁查两件事：
外壳里那个槽还在，且每个装外壳的页面真的调了 `mountShell()`——
只写 `<script src="shell.js">` 而不调用的话，页头不出现，作用域也就不存在。

- 个性化组：`正在编辑：几何 · 未应用` / `桌面正在用：流光`（与裁决 1 的第 2 层共用同一块）
- 自动化/系统组：`全局设置 · 不属于任何主题`

**理由**：这不是洁癖，它是 03 那一族缺陷的**根因**。一个全局作用域的页面上摆着一条
选中的主题轨，于是每行的「跟随全局」从不说全局是哪一个——README 缺陷 #30
实测「在侧栏把主题从几何切到流光，03 整页纹丝不动」。同族的还有 09 的缺陷 #19。
作用域不表达出来，这类缺陷会一直有新的形态。

## 4 · 光标皮肤：保留 11 状态，但换成能力包表达

**冲突双方**

- ux §7：「桌面端按两个可达状态设计，扩展端按六个」「状态导航只能保留一套」
  「预览必须模拟真实交互场景，不能把普通导航命名为『试用区』」。
- 稿子：11 个状态分 6 组，其中 9 个标「待系统能力」；且有「试用 / 校准」两个 tab。

**裁决**：状态数**保留 11**；「试用/校准」按 §7 重命名；
「待系统能力」的表达方式改成**能力包**（见裁决 4 的落地）。

**理由**：README 的论证成立——两个状态是**当前能力**的限制，不是这套皮肤体系应有的样子，
按两个状态画会把体系永久钉死。但稿子的表达方式有问题：9 行逐个贴「待系统能力」徽标，
用户看到的是**一个到处发灰的产品**，而且这些灰看起来是永久的。

**落地**：`07` 新增「解锁更多信号」一节，把 窗口几何 / AX 元素 / 屏幕取色 讲成三个可选能力
（各自写明代价：AX 覆盖率必然是部分的、取色需要屏幕录制权限），开启后相关状态**整组点亮**。
逐行徽标只保留**已解锁但这一次取不到**那一档——README 合并进来的能力分档一节已经指出，
这才是最让人困惑的状态：权限是绿的，效果却没跟着光标。

## 5 · 应用规则：采纳 ux §6.3 的三步引导

**冲突双方**

- ux §6.3：默认创建流程是 选应用 → 选行为 → 自然语言确认，主按钮「完成」；
  §6.1 句式「在「Visual Studio Code」中，使用「流光」主题。」；
  §10 要求 6 张低保真页面。
- 稿子：例外列表 + 挑选浮层；4 个原型态。

**裁决**：采纳三步引导作为**默认创建路径**，现有例外列表退化为「管理已有规则」。

**理由**：稿子的列表形态解决的是"已经有一堆规则怎么管"，而 §6.2 的 P0 前两条

这条验收指标唯一的兑现处。

## 6 · 措辞：「刚才使用的应用」，不是「当前应用」

**现状**：`刚才使用` 全稿 **0 处**；`当前应用` / `当前前台` 在 `03`/`05`/`09` 共 6 处。

**裁决**：采纳 ux §6.4，全部改成「刚才使用的应用」。

**理由**：这不是措辞洁癖。主进程每 250ms 采样前台窗口，并**刻意保留最后一个
非 CursorDance 的快照**（ux §6.4）。所以工作台置前时，"当前前台应用"字面上就是
CursorDance 自己——稿子现在的说法在**最常见的场景下是错的**。

## 7 · 创作型 Agent：已并入 `06`，对用户只有一个 AI 入口

**现状**：`surfaces/10-agent.html` 已由 commit `029e194` 以 `R100`（100% 纯重命名）
移到 `archive/10-agent-merged-into-06.html`，文件名自己写着「已并入 06」。
而 README 仍有**四处**坚持它独立（含整节标题「与 `06` 并存，不是替代」、
目录结构里两行重复条目）；`index.html` 仍链旧路径，页头仍写「10 页」。

**裁决**：确认合并。**两条工具链可以并存，两个产品概念不行。**

- 对用户只有一个 AI 入口，按意图路由：**调整当前场景 / 排查为什么没效果 / 从描述创建新场景**
- 前两种走 `06` 已定的五种 op（预设/字段/时间/曲线/开关）+ 逐项接受
- 第三种走归档稿里的效果程序链（DSL + 无头渲染 + 客观指标 + 新颖性距离），
  交付形态仍是「按段接受」，人是唯一写入者
- `archive/10-agent-merged-into-06.html` 保留为该链的形态参考，不再是一个页面

**理由**：归档稿自己论证得很清楚——`06` 的动作空间是枚举，所以它永远造不出第 9 种粒子。
那个论证仍然成立，成立的是**后端能力**层面；而"用户要在两个 AI 里挑一个"是
README 决策自己反对过的形态（`06` 那一版就取消了「快速 / Agent」模式选择，理由是
「模式是实现细节，不该由用户决定」）。同一条理由再上一层同样适用。

## 8 · `text-2xs` 统一为 11px

`DESIGN.md` 写 `text-2xs`（10px）；`docs/ui-spec/tailwind.config.cjs:22` 把它提到
`0.6875rem`（11px）、`line-height: 1rem`。

**裁决**：**统一 11px**，`DESIGN.md` 与根 `tailwind.config.js` 跟稿子改。

**理由**：11px 是走查时为了让「结论」可读而调的，`line-height` 与 `text-xs` 相同
（都是 `1rem`），所以提上去**行高零变化**，代价只是宽度涨约 9%。
两个配置不一致的话，按稿子重构出来的界面会比稿子更挤一档。

**配套**：ux §5 的硬约束「普通流程不使用 `text-2xs` 承载**必要信息**」——
2026-08-05 已按 03 的判据收敛全稿并加了 `text-2xs-budget` 门禁。**已完成**。

判据落地成两步，只有第二步是重命名：

1. 承载**结论**的 11px 一律提到 `text-xs`：按钮标签、读数值、状态徽标、表格里的值、
   空态、错误提示、作用域条、诊断面板的裁决条。
2. 合法的「补充说明」只有四种形态，收进 `_src.css` 成为组件类：
   `.hint-sub` / `.hint-note` / `.hint-inline` / `.hint-warn`（+ 三个 `ink-*` 深色版）。
   另有 `.glyph-badge`（单字头像，字号是几何约束）、`.stage-tag` / `.stage-note`
   （演示台构造标注）、`.proto-*` / `.vp-*`（**稿子脚手架，不吃产品预算**）。

第 2 步不是为了整齐：门禁按页计数时，40 处合法用法会把预算吃干，
于是真正的违规（一个 11px 的按钮标签）反而淹在计数里。

**收敛结果**：`04` 66→7 · `02` 50→5 · `01` 44→6 · `index` 38→1 · `06` 35→5 · `05` 31→5 ·
`library/controls` 31→1 · `07` 30→2 · `08` 22→1 · `09` 22→4 · `library/components` 66→6 ·
`shell.js` 52→5。全部落在默认预算 8 以内，所以门禁里的豁免表是**空的**——
空表本身就是结论：那些数字不是「这几页信息密度高」，是缺一个判据。

**2026-08-06 补记：上面那张收敛表有一个出口，第 1 步因此从未真正落地完。**

`text-2xs-budget` 门禁的 `collectFiles` 白名单只有 `.html` / `.js`——
**11px 一旦收进 `_src.css` 的组件类，就永久脱离了预算。**
于是「`library/controls` 31→1」里那个 1 是页面里剩的那一处，
而那一页 9 个滑块读数的 11px 全在 `.ctl-value` 这一行，**一次都没被数到**。
同族的还有 `.sl-bubble`（拖拽时唯一能看的读数，因为指针盖着别处）
和 `.count-badge`（动作页签上的「已启用效果数」）。

这与 `card-data-anchor-gone` 是同一形态：一个静默失效的门禁比没有门禁更糟，
因为它每轮都打印 PASS。

已修：三个类按第 1 步提到 `text-xs`。实测**行不变高**（两档 `line-height` 都是 `1rem`）、
`.ctl-value` 固定 74px 而最宽读数「2400 ms」在 12px 下 53px、
`.count-badge` 的 `h-4` = 16px 与 `text-xs` 行高恰好相同，
三档窗口下动作页签行都不需要横滚（620 / 860 / 1340 各自 `scrollW == clientW`）。

已补两道门禁堵住这个出口（判据见 `scripts/check-ui-spec.mjs`，
两条都做过「注入违规 → 确认报出 rule id → 还原」自测）：

- **`text-2xs-budget` 扩到 `_src.css`**，棘轮值 31 = 收敛后实测值。
  剩下的 31 处全是三族：`.hint-*` 四种合法补充说明、脚手架（`.proto-*` / `.vp-*` /
  `.stage-*` / `.gal-note`）、字号是几何约束的（`.glyph-badge` / `.app-icon-sm` / `.kbd`）。
- **`text-2xs-value-class`**：类名里出现 `value` / `readout` / `bubble` / `count` /
  `num` / `metric` / `out` 任一个词的组件类不得用 `text-2xs`。
  绑命名约定而不是一张手写清单——清单会漏掉下一个新类，
  而新类只要按现有约定命名就会被这条抓住（自测里造了一个 `.fps-readout`，当场报出）。

## 9 · 托盘：跟随 R1-6，降级成原生菜单

**冲突双方**

- `PROGRESS.md:75`：`[x] R1-6：取消桌面 Popup——删除孤立 renderer、HTML 和构建入口，
  托盘继续提供快速开关和打开工作台`。**已完成并验证**。
- 稿子：`09-popup.html` 是 320px 完整自绘面板，README 称其「最高频入口」，
  `08` 第 4 步还在说「看看托盘面板」。

**裁决**：跟随已完成的工程决策。`09` 改画成**原生托盘菜单**的样子
（启用/暂停、临时暂停三档、切场景、打开工作台），去掉自绘面板；`08` 第 4 步文案一并改。

**理由**：留着一个设计上核心、工程上已取消的半成品形态，是最坏的一种不一致——
它会让重构的人以为要把删掉的 renderer 再建回来。
ux §6.2 的两条 P0 创建任务由裁决 5 的三步引导承载，不依赖托盘面板。

**保留的问题**（不在本轮解决，但登记）：桌面工具的日常循环（暂停 / 换场景 /
在这个应用里关掉）确实比"进工作台调参"高频得多，而现在的 IA 给了 5 个等权入口。

## 10 · 动效规范拆成三层，L2 解禁 transform

**现状**：`DESIGN.md`「过渡动画」节禁止 transform 过渡（仅允许 `active:scale`）、
禁 `transition-all`、时长统一 `duration-150`、只过渡颜色/背景/边框。
全稿实测：`transition-colors` 91、`transition-transform` 16（几乎全是折叠箭头旋转）、
`transition-opacity` 2、`@keyframes` 0、`prefers-reduced-motion` **0**。
所有尺寸变化都是瞬跳：`#drawerBody` 内联 `height` 无过渡、侧栏 `w-[60px]↔w-[248px]` 硬切、
卡片折叠、列宽拖拽、分区切换同理。

**裁决**：拆成三层。

| 层 | 范围 | 规范 |
| --- | --- | --- |
| **L1 反馈层** | hover / active / 选中 | 120–160ms，只动 color/opacity/box-shadow。沿用现状 |
| **L2 布局因果层** | 抽屉、侧栏、卡片折叠、列宽、分区切换 | 180–220ms `ease-out`，**允许 height/width/transform** |
| **L3 内容效果层** | 舞台里的效果本身 | 由用户配置决定，不受 UI 规范约束 |

`transition-all` 仍然禁止（改为列举属性）。`prefers-reduced-motion` 从"建议"改成
**硬约束**：L2 降为 0ms，自动重播/骨架脉冲/AI 跳点关闭，仅保留手动预览。

**理由**：那一节是为**扩展的设置表单页**写的，现在拿它管一个**动效创作工具**。
后果不是"不够精致"，是**丢信息**：抽屉一展开，舞台从 279px 掉到 240px、
播放控制条被整条盖住（P1 的 A1），瞬跳让用户根本读不出是谁挤了谁。
L2 的职责是**表达因果**，不是装饰。

## 13 · 补齐三条时间轴通道，并定下它们的时间关系

**现状**：卡片列 8 张卡，时间轴 5 条轨（触发/波纹/粒子/飘字/音效）。
**动画 / 贴纸 / 光标反馈**在舞台上没有任何出场时机——调什么都不会发生，
而界面上 8 张卡看起来完全同权。它们的 19 个字段此前整族登记在 `PREVIEW_EXEMPT` 里，
理由写的是「没有通道」。

**裁决**：那个理由是**该修的，不是该豁免的**。补齐三条通道，时间关系如下：

| 通道 | 锚在 | 偏移 | 时长 | 理由 |
| --- | --- | --- | --- | --- |
| 光标反馈 | `trigger` | 0 | 240ms | 光标是用户的手，按下那一刻就该有回应。它是**唯一一个应该在任何效果出现之前就到位**的反馈——晚于效果会被读成"卡了一下"，而不是"我按到了" |
| 动画 | `trigger` | 0 | 420ms | 命中点上的形变，属于直接命中反馈，与触发同时起、比波纹短：要在波纹还在扩的时候收尾，否则两个都在动、读不出是对谁的回应 |
| 贴纸 | `ripple.peak` | 0 | 900ms | 它是**内容**，与飘字同族：等波纹峰值把注意力带到命中点之后再出现。在波纹还没铺开就蹦出来的贴纸会盖掉"这里发生了什么"这条线索本身 |

**落地约束**：三条通道跟着 `cardOn()` 过滤，而三张卡默认关着，
所以**默认视图与补齐之前逐像素相同**——刻意如此，避免一次结构补齐顺手改掉默认观感。

**顺带推翻一条旧理由**：光标反馈原先的豁免写的是「舞台里没有真实光标可改，02 才是它的界面」。
那站不住：真实实现本来就有一层软件光标（`src/desktop/renderer/engine/cursor-overlay.ts`），
命中反馈作用在它身上。所以舞台该画的不是"系统光标"，是那一层覆盖物。
**`02` 管皮肤长什么样，`01` 管被敲击时它怎么反应**，两件事。

19 条豁免因此解除 17 条，剩下两条是稿子的真实边界（不加载真实位图 / 拖尾需要历史帧）。

## 15 · 页头：删掉「已是最新」，换成全局暂停；导航改回 nav 语义

**现状（两个实测缺陷）**

1. 「✓ 已是最新」是**写死的静态文本**，不在 `scopeSlot` 里、不受任何状态驱动。
   而它就贴在作用域条旁边，于是改一个字段之后同一行同时显示
   「未应用」和「已是最新」——**自相矛盾**。它想说的大概是「应用版本已是最新」，
   但放在草稿状态旁边只会被读成配置状态。
2. 工作区导航是 `role="tablist"` + 5 个 `role="tab"`，而**同文档 0 个 `role="tabpanel"`**，
   其中 4 个是 `<a href>`、点了整页跳走。读屏器会报「标签页 1/5」并等着面板出现，
   然后文档直接卸载。

**裁决**

| 位置 | 改成 | 理由 |
| --- | --- | --- |
| 「已是最新」那块 | **全局暂停 / 恢复**（三档与 `09` 逐字一致：20 分钟 / 1 小时 / 直到重启） | 裁决 9 登记过一个没解的问题——桌面工具的日常循环（暂停 / 换场景）比"进工作台调参"高频得多，而暂停只能去托盘。放在这里**不需要推翻 R1-6**：它是工作台窗口内的一个控件，不是被取消掉的那个自绘托盘面板 |
| 工作区导航 | `<nav aria-label>` + 当前项 `aria-current="page"` | 跨文档导航该用的属性。tab 模式要求同文档有 tabpanel |
| 组标签（个性化/自动化/系统） | 只在 lg 档显示（原先 md 也显示） | 分组的收益是作用域清晰，由主题侧栏/撤销/草稿状态的显隐承担（裁决 2 的落地约束），不依赖这三个词；竖线已经把分组画出来了。而它们在 md 档吃掉约 120px，那一档的预算刚够五个 chip |

**暂停与「草稿 / 已应用」是两个正交的轴**：暂停不改配置，应用不改运行开关。
所以两者并排不打架——这恰恰是「已是最新」做不到的事（它和「未应用」在同一个语义轴上）。
状态存 `sessionStorage`：它是全局运行态，跨页导航不该丢；用 `localStorage` 会变成
「上次退出时暂停了，这次打开还是暂停」——一个自己不会恢复的暂停比没有暂停更糟。

**门禁的责任，登记下来**：上一轮的 `aria-state-missing` 只问「有没有状态属性」，
没问「这个 role 用对了没有」，于是把 `aria-selected` 逼到了链接上——
**是门禁把一个错的模式固化住的**。已补两条判据：
`aria-current` 计入合法状态属性（且它只写在当前项上，缺席即"不是当前项"，
所以不再逐个报非当前链接），以及 `tab-without-tabpanel`。
后者立刻又抓出两处真的：`01` 的动作页签、`03` 的挑选页签——
两处都**确实**在切同文档的面板，所以补的是 `role="tabpanel"`，不是降级 tab 语义。

## 16 · 「已启用」改成低权重编码，实心深底留给主操作

**冲突双方**

- README 决策 #3 的落地形态：「深底图标=启用、浅灰=关闭」，`_src.css` 的
  `.cfg-icon-on { bg-slate-900 text-white }`，真实代码 `panel.tsx:12` 的
  `ICON_TONE_ENABLED = "bg-slate-900 text-white"`。
- `DESIGN.md`「选中态的权重」三条：**实心深底只留给页面主操作**（一个页面只能有一个视觉主操作）、
  **一屏出现 3 个以上 `bg-slate-900` 实心块就说明权重用错**（在反模式清单里）、
  **选中态必须同时有非颜色的编码，不能只靠深浅**（也是 a11y 要求）。

**裁决**：采纳 `DESIGN.md`。启用态改成低权重——**底色两态相同**，
变的是字形深浅（`text-slate-400` → `text-slate-900`）加一圈 `ring-slate-900/15`。

**理由三条，其中第三条是决定性的**

1. 效果卡是 **8 张同权卡片**，不是一个主操作。按旧画法，全部启用时一屏 8 个最重权重的块，
   而真正的主操作（「应用到桌面」）和它们长得一样重。
2. 旧画法**只靠深浅**。非颜色编码不需要新加：卡头最右侧本来就有一个 `role="switch"` 的开关，
   拨柄位置就是它——`01` 卡头那段注释已经论证过「不要第三次编码同一个 bit」
   （那次删掉的是第三处「已启用」文字徽标，理由相同）。
3. **旧画法在深色模式下不存在。** `bg-slate-900` 落在 `.surface`（深色下也是 slate-900）上，
   实测对比度 **1.00**——启用与关闭的区别整个消失。一个在深色下不存在的状态编码等于没有编码，
   而 `library/components.html` 恰恰是深色令牌层唯一的验证处，它自己没通过。

**影响**：`_src.css` 的 `.cfg-icon` / `.cfg-icon-on`（补深色分支）、
`01` 的 8 张效果卡（只改类定义，模板不动）、`library/components.html` 第 D 节。
实现侧要跟着改 `panel.tsx` 的 `ICON_TONE_ENABLED` / `ICON_TONE_DISABLED`。

**保留问题（登记，不在本轮解决）**：同一条冲突还剩 8 个组件类在用实心深底表达
「并列项里的当前项」——`.seg-item-on` / `.action-tab-on` / `.preset-chip-on` /
`.ws-chip-active` / `.edge-chip-on` / `.tl-iconbtn-on` / `.layout-btn-on` / `.preset-tile-on`。
它们分布在 5 个界面共 24 处以上，改一遍要连三档窗口一起重走查，
所以需要一次独立的产品决策。**不写下来的话这就是第 9 次静默反转**。

顺带说明一件容易被误读的事：`library/components.html` 作为**画廊**同屏摆了十几个组件的选中态，
所以「一屏 ≤2 个深底块」这条判据在那一页上不适用——它约束的是产品界面。
而 `01` 是产品界面，8 张效果卡就是 8 个。

  「缺席没有视觉痕迹」这条教训对门禁自己同样成立，且更糟：一个静默失效的门禁会让人**更**放心。

**2026-08-05 第二批**，又补了三条（都是当天踩到的形态）：

- `cross-script-lexical-collision` —— 页面内联脚本的顶层 `const/let/class`
  不能与 `shell.js` / `controls.js` 里同名。经典脚本的顶层词法声明进的是**共享的
  全局词法环境**，重名会抛 `SyntaxError` 且**整段页面脚本一行都不执行**。
  实测表现：页面照旧渲染（标记是静态的）、配置列与时间轴全空、控制台无可读记录，
  而门禁 PASS——因为 `inline-script-syntax` 对每段脚本**单独**跑 `new Function()`，
  单独看两段都完全合法。「分别检查都通过、合起来是坏的」。
- `measured-geometry-without-viewportchange` —— 用 `getBoundingClientRect` /
  `clientWidth` / `clientHeight` 的页面必须听 `viewportchange`。
  **切换窗口尺寸档不触发 `resize`**（变的是 `#mockWindow`，浏览器视口没动）。
  实测：`01` 切到最窄档后舞台只分到 47px（最小需求 240），而 A1 那条纵滚兜底
  **从未在切档路径上执行过**；`02` 的校准图钉停在上一档的像素位，
  而旁边的坐标读数仍然是对的——**位置错、数字对**。
- `icon-button-unnamed` —— 纯图标的 `<button>` / `<a>` 必须有
  `aria-label` / `title`。稿子里这类控件很多（折叠箭头、⋯ 菜单、播放控制、色板格）。

三条判据在落地时被**加宽**，理由都是「原判据有结构性盲区」：

- `aria-state-missing` 除了按 `_src.css` 的 `-on` / `-active` 变体**推导**组件类，
  还加了一道「按形态认」：`<button>` 用三元表达式自己画选中态（`bg-slate-900/950` 实心）
  也算违规。因为绕过组件库手写的选中态，第一道判据一个都看不见——
  而实测就有五处（`02` 的试用/校准、`03` 的挑选页签、`04` 的 knob、`06` 的逐项接受…）。
- 同一条规则的右边界必须把 `${` 算作边界：稿子里最常见的写法是
  `class="action-tab${on ? …}"`，基类紧跟模板占位符、中间没有空格。
  只认 `\s|$` 的那一版让整族漏检（实测 5 个动作页签一个 aria 状态都没有，门禁 PASS）。
- 同一条规则还必须**整源扫描而不是逐行**，并且覆盖**非 button** 的可交互元素：
  开标签经常跨行（主题列表那一行的 `class=` 在第二行），逐行匹配时
  第一行没有 `>`、第二行没有 `<div`，于是 `<div role="option">` 那一族整个漏检；
  而 `<a role="tab">`（外壳页签）同样不是 button。
  判据现在是「带状态类 **且** 有 role/tabindex/href」——
  纯装饰的 `<span class="switch-knob">` 靠这一条排除，而不是靠标签名。
  三处都做过注入自测（删掉 `aria-selected` 后确认报出）。
